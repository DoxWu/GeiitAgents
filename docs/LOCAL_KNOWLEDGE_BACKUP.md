# 本地知识库加密备份与恢复

实现日期：2026-09-20。此功能针对客户端本地库，与管理员 PostgreSQL 异地备份 API 独立。文件不上传服务器。

## 使用

在「本地知识库」关闭本地模型，进入「备份与恢复」。导出时输入并确认口令，下载 `.geiitkb` 文件；恢复时输入该文件口令，选择文件，查看文档数、片段数和模型，再点「确认替换本地库」。预检查或取消不会修改当前库；恢复是整体替换，不合并，同名文件不特殊处理。先导出旧库才能保留其历史副本。

文件包含完整文档、片段来源、向量及独立 embedding 配置，不含模型权重、聊天对话、API Key 或云端数据。恢复无需启动模型或联网；恢复后模型仍关闭，需手动启用。首次在新设备启用时需要下载对应模型，已有完整缓存可离线使用。

备份口令仅在组件操作期间使用，操作结束清空输入，不写本机设置或云端。允许 4–256 字符，建议长口令；遗失不可恢复。**备份文件加密不等于本地 IndexedDB 加密**，当前运行中的原文和向量仍明文保存，同一客户端数据目录的账号共享。

## 格式和保护

- 外层 JSON：固定格式 `geiit-local-knowledge-encrypted`、version 1、PBKDF2-SHA256/600,000 次、随机 16 字节 salt、AES-256-GCM/随机 12 字节 IV，密文为 base64。算法/版本绑定 AAD，不接收任意 KDF 参数。
- 文档名、模型名、导出日期等均在加密载荷中。密文认证失败统一报「口令不正确或文件已损坏」。AES-GCM 检查完整性，不证明外部备份内容来源可信。
- 导出先构造字段白名单，排除未知属性；导入拒绝超限文件/未知版本/指纹不一致/重复 ID/路径式文件名/错误维度/非有限或非归一化向量/来源偏移与原文不一致/文档缺失片段，并重新计算 UTF-8 文档大小。
- 文件上限 180 MiB，明文载荷上限 128 MiB；原文本身继续受 100 文件、10 MiB 合计、2 MiB 单文件、2000 片段上限保护。首版整文件在内存中处理，无压缩、分卷或流式序列化，峰值内存仍需压测。
- 预检查捕获当前索引 revision。提交时再次取得同一个 Web Lock，以 IndexedDB 比较交换事务写入；如其他窗口已修改库则拒绝覆盖。导出同样持锁并读取最新完整快照。
- 恢复会生成新 revision；向量仍绑定原 embedding 指纹。不能用不同模型查询；语义正确性不能仅靠向量数值校验保证。

## 开发与验证入口

- `frontend/src/localKnowledge/backup.ts`：格式、加解密、完整结构校验。
- `frontend/src/components/workbench/LocalKnowledgeBackup.tsx`：导出/预检查/确认/取消/锁与事务流程。
- `frontend/src/localKnowledge/backup.test.ts`：真实 WebCrypto 往返、随机盐与 IV、错误口令、篡改、限额、错误模型/向量/片段等 14 项测试。
- `frontend/scripts/verify-local-backup.mjs`：生产前端预览（端口 1423），真实文件下载/导入、IndexedDB/WebCrypto；设置 `LOCAL_BACKUP_NATIVE=1` 时检查 `target-dev/release` 的实际 Windows 开发版。使用独立 QA 数据目录和固定测试向量，不把这项检查描述为真实 embedding 质量测试。

本批不增加定时客户端备份或后台云同步。用户选择保存的位置由浏览器/WebView 下载机制管理；页面发起下载不等同于文件一定保存在预期目录。后续可增加原生保存对话框、备份历史、本地存储加密与大库流式处理。
