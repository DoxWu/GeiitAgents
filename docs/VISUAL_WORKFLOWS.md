# 本机可视化工作流

更新：2026-10-01。入口为工作台 → 任务 → 可视化工作流。手动运行 DAG，运行输入可粘贴或导入受限 CSV/XLSX；XLSX 使用与图表工具相同的本地解析限制。不是云端调度服务。定义编辑会自动暂存为工作台密钥库中的加密草稿，不增加正式修订号；本次运行输入不进入画布草稿。工作流、转换后的 CSV 运行输入、检查点和成果另随密钥库加密保存；原始 XLSX 不保存在快照中，本地知识库及其模型/向量不参与此执行器。

已保存定义可导出为不超过 512 KiB 的 `geiit-workflow-definition` v1 JSON，并在另一客户端导入。导入会校验完整节点字段、引用、条件分支及无环拓扑，给工作流和所有步骤重新生成本地 ID，修订归零；节点专属模型连接 ID 会从导出文件移除。导入仅载入加密编辑草稿，不会覆盖现有定义或自动执行；用户必须检查并显式保存。模型 Key、运行输入、运行历史与成果不属于便携定义。

## 配置与运行

1. 新建工作流，添加步骤。在画布中拖动步骤标题上方的移动按钮，或聚焦该按钮使用方向键调整坐标。画布工具支持 60%–150% 缩放；“自动排列步骤”按依赖层级生成确定性坐标，只改变坐标，不改变节点、连线或执行顺序。缩放后拖动会按画布比例换算位移。
2. 编辑节点参数，用“前置步骤 / 后续步骤”连接。支持多个前置结果汇合与一个步骤连接多个后续步骤。条件分支节点可按参考材料、CSV 或直接前置结果进行文本/数值判断；它的每条出线必须标注 `true` 或 `false`，命中的出线执行，未命中的后续节点记录为成功的“跳过”。汇合节点等待全部前置步骤完成或跳过后，只要有一条有效入线就执行，仅收到有效前置结果；全部入线未命中或被跳过时继续跳过。因此互斥分支可以重新汇合。一个目标步骤的入线不能混用条件分支线与普通线。自连接、重复、缺失节点和环路会被拒绝。无连接节点也会执行；画布坐标不决定执行顺序。
3. 画布编辑会在约 500 ms 停顿后加密暂存到本机密钥库；临时不完整字段保留最后一个有效草稿。刷新或重新解锁后可恢复。切换定义时会提示放弃未正式保存的修改；锁库会先冲刷排队中的草稿写入。点击“保存工作流”才生成递增修订，只有正式保存的定义才能运行；修订冲突需重新载入。草稿写入失败时界面明确提示，仍需用户重试或检查存储。
4. 填写本次参考材料，并粘贴 CSV 或导入 UTF-8 CSV/XLSX。XLSX 只读第一个可见工作表并显示名称；文件上限、公式/错误/合并格拒绝策略与图表工具相同。导入后得到的 CSV 是本次输入，解析失败不覆盖现有文本。工作流默认模型供所有模型节点继承；可在单个模型生成节点中覆盖连接。纯本地工作流无需模型或联网。只要任一节点路由到云端，本次运行就须单次勾选授权；输入、定义、节点路由、模型/账号变化使授权失效。
5. 手动运行。先验证整个图与可静态验证的 CSV/图表，再建立加密运行快照；按拓扑顺序逐节点执行，独立节点按定义顺序取用，不并行。每节点执行前保存 running，执行后保存状态与成果，再开始后续节点。

| 节点 | 行为 / 数据来源 |
| --- | --- |
| 检查 CSV | 复用现有 CSV 解析器，读取本次 CSV，返回表头/行；不执行单元格公式 |
| 生成图表 | 复用本地柱状/折线图工具，按显式选择的分类列、1–6 数值列与单位生成 SVG；使用原始 CSV，不根据模型猜测数据 |
| 整理 Markdown | 用户正文可附加本次参考材料，连入的前置步骤结果始终附加。CSV 检查结果为 JSON；图表结果为成果名称、ID、摘要与警告，不直接嵌入 SVG |
| 模型生成文档 | 用用户生成要求、连入的直接前置结果，以及可选本次参考材料/CSV，调用既有严格流式文档生成；不发送无连线节点结果，不读取其他文件 |
| 条件分支 | 对选定来源执行包含、不包含、等于、不等于、有内容、为空或数字比较；结果保存为 `true`/`false`，只启用对应标记的出线 |

模型节点默认使用本次运行选择的工作流模型；节点可按已保存连接 ID 单独覆盖，也可单独选择账号云端模型。模型 Key 不进入工作流定义或运行快照；仅从解锁密钥库取得请求用 Key。仍被保存定义或运行中工作流引用的连接不能删除。云端授权覆盖本次运行中所有最终解析到的云端节点。最多 6 次模型调用，每步骤 120 秒，工作流总计 12 分钟；最多 3 个模型/工作流同时占用执行槽位。工作流没有模型自主选择工具、脚本、任意网络、邮件发送或磁盘写入权限。

## 完成、中断与版本

- 模型节点沿用 Web 本机、Tauri 本机、私人云端转发和授权账号四条严格流式路径，预览沿用 16000 字符/60 ms 合并。EOF 缺少结束证据会失败。
- 模型报告 `length`、`content_filter`、`tool_calls` 或 `unknown` 时保留带停止原因的成果，但整个工作流失败并停止后续节点。这样不会把未确认完整的回答继续交给后续步骤。单独文档生成的保留策略仍独立。
- 每次运行固定定义修订和输入快照。之后编辑/删除定义不改变历史。复制历史快照创建新的未保存工作流，不复用旧运行 ID、不自动重放；新运行可能再次计费。
- 停止或锁库关闭当前传输；迟到结果不保存。重新解锁时将未结束任务/步骤标为 interrupted，并保留此前成功检查点和成果；运行状态恢复不代表自动继续。切换工作台页签可继续已开始的执行，关闭客户端不能后台执行。
- 初始/步骤前记录保存失败时不执行后续操作。成果已进入内存但最后保存失败时可以重试本机保存或整库备份，不自动再次调用模型。跨窗口密文冲突沿用密钥库保护。
- 运行历史每页显示 10 条，可翻页查看记录；翻页会清除旧选择并默认选中当前页首条。每步结果、成果选择、Markdown/SVG 下载和已有 DOCX 导出仍按所选运行展示。失败运行的已保存文档也可导出，非正常停止原因保留。DOCX 只有下载/XML 验证，尚未完成逐页版式验收。

## 容量与备份兼容

最多 30 个定义，每图 12 节点 / 66 连线 / 6 模型节点；坐标限制在 0–2000。复用 100 个办公任务总上限。参考材料 50000 字符、CSV 100000 字符（50 行/12 列）；导入 CSV 文件不超过 400 KB，XLSX 不超过 2 MB，并沿用图表导入的 ZIP/XML/单元格上限。单次模型来源 JSON 最大 100000 字符，本地拼接 Markdown 最大 50000 字符，超出会明确停止，不静默截断。模型完整回答仍沿用原 1000000 字符限制。实际 localStorage 配额可能早于数量上限耗尽。

`VaultData.workflows` 保存正式定义，`VaultData.workflowDraft` 保存可选的未正式保存草稿；`TaskRun.workflow` 保存运行快照；`ToolRun.workflowNodeId` 关联节点。备份逐一校验结构、未知字段、节点引用、拓扑、节点/工具对应和成功任务的完整检查点。定义、草稿、快照、检查点均纳入 `.geiitwork`；恢复不执行任何节点。含 `workflowDraft` 的备份需要 dev.37+；旧客户端按未知字段拒绝。旧客户端回写现有本机库可能丢字段，不支持保留新数据的降级。

新增画布使用原生 HTML/SVG，无新增运行依赖。工作流页面、定义校验和执行器按需分包；CSV/XLSX 解析只在用户选择导入时动态加载，JSZip 仍只在解析 XLSX 时按需加载。多步骤与工作流复用单独的 `ToolArtifact` 展示组件，不为进入工作流而加载整个旧工具任务界面。

## 本地验证与限制

新增领域/存储/界面 26 项，最终前端全量 101 文件 / 972 项通过。包括真实本地图表生成、环路/非法定义、静态预检、直接依赖和输入选择、非正常停止、超大模型上下文、纯本地输入边界、写前/写后保存失败、取消/锁库/登出、修订冲突、加密恢复/备份和 UI 授权失效。

`frontend/scripts/verify-workflows.mjs` 提供 Web、`--relay`、`--account`、`--native` 实际页面验收，隔离 origin / WebView 数据，动态端口。检查拖动/键盘布局、三节点分叉汇合、环路拒绝、实际 Markdown/DOCX 下载、刷新恢复，再增加模型节点检查增量/正常结束/输出上限/EOF/停止/锁库，以及实际加密备份下载、预检查、整体恢复后不重放。每模式 5 次合成生成 HTTP 请求，纯本地阶段零模型请求。云端模式使用实际 FastAPI 路由/HTTP 传输，认证/选模/上游为 fixture；不代表线上登录、真实供应商或计费验收。续跑、单节点重试、检查点复制、历史快照固定和云端重新授权由工作流存储/组件回归覆盖。原生结果、构建摘要和最终通过状态以 [工作记录](WORK_LOG.md) 为准。

尚未实现：循环、定时/事件触发、任意插件工具。定义独立导入/导出和历史分页、画布缩放/自动布局已实现。失败/中断/取消续跑和单节点重试已实现，但仍需低配、最大容量、强杀/断电及真实供应商验收；DOCX 分页也仍待受支持的渲染环境。
## Resume and retry (2026-10-01)

Failed, interrupted, or cancelled workflow runs can create a new continuation run from history. The default resumes at the first incomplete step; a failed step can also be selected for retry. Completed checkpoints and artifacts are restored as inputs without repeating their model or tool calls. The continuation receives new task, tool-run, and artifact IDs while the original history remains unchanged.

Continuation always uses the original workflow revision and input snapshot. Cloud model steps require fresh consent. Missing prerequisite checkpoints or artifacts reject the continuation before any model request.

The older limitation list above predates this change; single-step retry and continuation are now available through run history. Other listed limits remain unchanged.
