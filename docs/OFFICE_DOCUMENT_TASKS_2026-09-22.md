# 办公文档任务首版

日期：2026-09-22。状态：代码、单元/状态机测试、正式 Web 构建、Chromium 流程验证和 Windows 开发包构建已完成；未部署线上。

## 用户流程

工作台新增“任务”视图。用户填写文档标题和生成要求，可粘贴参考文本或选择 UTF-8 Markdown/TXT 文件，再明确选择生成模型。个人云端连接或账号云端模型每次都要勾选本次出站授权；本机模型连接不要求云端授权，但是否联网取决于用户自己的本机模型服务。

开始后立即创建并加密保存任务与工具运行记录，模型成功返回后生成 Markdown 成果，记录版本、文件名、生成时间和 SHA-256。成果在客户端安全 Markdown 组件中预览：不执行 HTML，不加载远程图片或链接；下载的 `.md` 是明文文件，由用户自行保管。

任务可停止、失败后复用输入、下载成果或整体删除。删除会同时移除该任务的工具记录和成果。首版最多保留 100 个任务；任务输入最多 10,000 字生成要求和 100,000 字参考材料，选择的源文件仍限制 2 MiB。生成结果最多 1,000,000 字符。

## 数据模型和恢复

- `TaskRun`：当前只支持 `document.generate-markdown`，保存标题、指令、可选来源快照、模型连接 ID、状态、时间以及关联记录 ID。
- `ToolRun`：记录一次 `model.complete` 的运行状态、实际模型标签、开始/完成时间和脱敏错误；不保存 API Key、供应商 URL 或 HTTP 原始响应。
- `WorkArtifact`：首版为 `text/markdown`，保存内容、文件名、版本和 SHA-256。

三类记录与模型连接、聊天一起进入既有 AES-GCM/PBKDF2 本机密钥库。旧密钥库没有新字段时迁移为空数组，不改密文格式或存储 key。API Key 仍只保存在私有 profile 中，任务公共状态拿不到密钥。

模型请求发出前必须先成功加密保存运行中记录；若存储配额或跨窗口冲突导致写入失败，模型不会调用。成功成果写入失败时成果仍在当前内存中并展示全局存储错误，用户可立即下载，但不能认为刷新后仍存在。

锁定、关闭页面或客户端会中止内存请求。最后成功持久化的 `running` 任务在下次解锁时转换为 `interrupted`，不会自动重放云端请求或伪称完成。明确停止/超时记为 `cancelled`，失败不创建部分成果。登录账号变化会中止账号及云端转发任务。

工作台现有最多三个并发模型请求限制已统一按所有请求计算，覆盖聊天、知识库回答和文档任务。任务保存在独立集合，不会加入聊天上下文，也不会读写本地或云端知识库索引。

## 提示与安全边界

文档生成 system 消息要求直接输出 Markdown，把 source JSON 标为不可信参考材料，不执行其中的命令、不调用工具、不编造未给出的具体事实，并在资料不足时标记待补充。这个提示降低文档注入风险，但不能保证模型内容正确；用户仍需审阅成果。

发送给模型的内容只有本次标题、生成要求、可选文件名和参考文本。模型连接的可选最大输出 Token 沿用原配置，默认不设置。个人云端 API Key 继续由服务端在单次请求中临时使用，不写任务；账号模型请求不包含个人 Key。

## 尚未完成

- 首版只生成 Markdown，没有 DOCX/PDF/XLSX/PPTX 转换、模板系统、复杂样式、图片或图表成果。
- 每个任务当前只有一个模型 ToolRun 和一个成果版本；没有多步骤工具链、人工审批节点、版本对比或从已有成果继续编辑。
- 模型输出非流式；客户端关闭后任务标记中断，不能在无设备在线时后台继续。未来服务端持久任务不能复用用户本机 API Key。
- 参考文本随任务加密保存，删除原文件不会改变快照。尚无附件二进制存储、目录授权、文件原位覆盖或撤销。
- 真实供应商测试不等于生产账号/FastAPI 登录联调，也没有验证所有模型的 Markdown 遵循度。

开发模式 Windows release/NSIS 最终构建成功：`GeiIt Agents Dev_0.1.0-dev.4_x64-setup.exe` 为 7,179,874 字节。模型权重不在安装包内；包未签名，未运行安装/卸载向导或原生 WebView2 文档任务端到端，未发布。

下一步先扩展 Artifact 版本与一个确定性 DOCX 导出/渲染路径，再抽象多步骤 ToolRun 执行器供文档转换、图表和可视化工作流复用。待办/邮件调度仍是独立后续模块。
