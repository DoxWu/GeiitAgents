# 本机笔记、待办草稿与归档

更新：2026-09-29。本文描述客户端实现；本机记录与服务端账号记录/邮件提醒分别管理，不自动上传、关联或调用模型。它们属于当前本机密钥库，**不按云端登录账号隔离**。同一客户端数据目录中，持有相同解锁口令的使用者可以查看这些内容。

## 原始编辑与正式记录

- 每条正在编辑的记录拥有独立草稿，新建草稿先分配 UUID。草稿保存完整原始输入，包括空标题、原始标签文本、截止时间文本、IANA 时区、所依据的正式修订号与编辑标识。
- 输入立即更新内存，停止输入 400 毫秒后通过现有 AES-GCM 密钥库合并保存。更早的加密写入完成不能清除较新编辑的待保存状态。离开本机记录视图会尝试冲刷，手动/闲置锁库在清空内存前提交当前待保存快照，并等待队列完成。
- 切换笔记/待办、正式记录或工作台模块不丢弃已进入草稿的编辑。重新打开默认恢复最新草稿，侧栏可选择其他草稿。丢弃必须确认，只丢弃草稿，不删除正式记录。
- 正式保存先校验并持久化原始草稿，再检查编辑标识/修订号；新正式记录与对应草稿删除在同一加密快照中写入。提交等待期间发生较新编辑，旧提交被拒绝。
- 正式记录改变/删除时，保留冲突草稿。可明确丢弃并载入最新记录，或者另存为新草稿；复制不删除原草稿。删除正式记录也不会连带删除编辑草稿。
- 每库最多 100 条草稿、500 条正式记录，归档仍占正式记录名额。达到草稿上限后，新编辑入口禁用，已有草稿可继续编辑、保存或丢弃，不自动淘汰旧内容。

草稿使用创建时的固定时区，之后设备改时区不会重新解释截止时间。正式待办保存 UTC，显示到分钟但未改变时间输入时保留原 UTC 秒数。新截止时间限制在 1970–2100 年；夏令时不存在/重复的时刻拒绝提交，需另选时间。本机待办只排序/提示逾期，不自动发邮件。

## 写入失败与恢复

界面区分待写入、已加密保存、写入失败和未进入草稿。写入失败后可导出当前原始草稿，或“重试本机保存”。若最后一次正式写入失败，保留内存中的正式记录和失败提示；重试只写当前快照，不重复创建或增加修订号。上次成功持久化的原始草稿仍可在重新解锁后恢复。如果用户选择锁定而冲刷仍失败，只能恢复最后一次成功写入的快照。

这不是跨窗口合并机制：密钥库沿用对另一窗口写入的检测，不自动覆盖不同窗口的密文。存储失败或异步写入完成前的强制退出不能保证最后字符已保存。浏览器清理站点数据、口令丢失、磁盘故障仍可能造成数据丢失。

新版本兼容没有 `personalDrafts`/`archivedAt` 的旧库；反方向降级没有数据保留承诺。旧版开发客户端与新版使用相同 dev 数据目录，旧代码重新保存可能丢掉它不认识的草稿或归档字段。不要把旧包覆盖运行视为迁移/备份方案，升级/降级流程尚未验收。

100/500 是记录数量限制，不是容量承诺。密钥库仍整体加密写入 localStorage，长内容、会话、任务成果与草稿共用存储配额；可能在达到条数上限前就写入失败。最大容量/低内存/突然断电测试和分块持久化仍待完善。[工作台加密备份](WORKBENCH_BACKUP.md)现已包含正式记录和原始草稿，可在存储写入失败时导出当前内存快照。

## 归档、恢复与导出

- 单条或批量归档/恢复先检查全部选中 ID 与修订号。存在草稿、旧修订、已删除记录或当前存储错误时拒绝变更整批。
- 归档只设置 `archivedAt` 并增加修订，不改正文、状态、完成时间或截止时间。已归档待办不再计为逾期，恢复后按其原状态判断；恢复前不可编辑。重复设置相同归档状态不会增加修订。
- 未归档/已归档/全部记录可搜索筛选。改变搜索、类型、状态或归档筛选会清除勾选，避免把不可见的旧选择带到新结果中。
- 批量 Markdown/JSON 只导出明确勾选且修订仍匹配的正式记录，不混入草稿或未选择内容。归档记录也可导出；单条正式内容和当前原始草稿可分别下载。
- 所有这些下载均为**明文**。JSON 正式记录格式为 `{ format: "geiit.personal-records", version: 1, exportedAt, items }`；当前没有 JSON/草稿文件导入界面，不能把此导出描述成可一键还原的加密备份。
- 本机归档、恢复、删除、完成待办不会取消或修改独立的服务端邮件提醒。服务端提醒的管理与边界见 [个人记录与邮件提醒 API](PERSONAL_RECORDS_API.md)。
- 完整迁移使用工作台 `.geiitwork` 加密备份，包含正式记录和草稿，恢复前预检查、确认后整体替换。上面的明文选中记录 JSON 仍没有单独导入/合并入口。

## 代码与验证入口

- `frontend/src/personal/itemDraft.ts`：原始草稿、校验与固定时区转换。
- `frontend/src/personal/items.ts`：正式内容、归档状态、整批修订检查和导出。
- `frontend/src/store/workbenchStore.ts`：草稿合并写入、锁库冲刷、原子快照提交及归档。
- `frontend/src/components/workbench/PersonalItems.tsx`：恢复、冲突、写入失败、筛选/勾选/下载。
- `frontend/scripts/verify-personal-items.mjs`：生产 Web 验收，默认创建自己的动态预览端口；可通过 `PERSONAL_QA_URL` 指定已启动的预览，`--native` 使用开发 exe 与隔离 WebView2 数据目录。

脚本只使用合成记录，验证实际下载字节、持久密文、切换视图/立即锁库/刷新、设备时区改变、写入故障与修订不重复、归档恢复/冲突、删除后的草稿另存、无额外 API/模型请求。Web 另验 390px，无真实邮件。最新实际验证、包版本与限制以 [工作记录](WORK_LOG.md) 为准；代码实现、本地验证、安装包和线上部署分开记录。
