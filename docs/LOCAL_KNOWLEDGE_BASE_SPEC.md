更新日期：2026-09-20。状态：首版代码、浏览器与 Windows 实机验证、Windows 验证包已完成。支持主动启用 E5、Markdown/TXT 索引与检索、独立配置和缓存、自定义兼容模型重建；尚非完整 RAG 或大规模性能验收。实际范围、固定资源清单、测试及限制见 [首版实现说明](LOCAL_KNOWLEDGE_BASE_IMPLEMENTATION_2026-09-20.md)。下列为完整实施约定，未覆盖的条目仍属后续目标。

## 已确认边界

同日后续已补充 [加密备份/恢复](LOCAL_KNOWLEDGE_BACKUP.md)、[Git 与开发包隔离](VERSION_CONTROL.md)、[检索回答生成](LOCAL_KNOWLEDGE_ANSWERS.md)。运行时原文/向量仍未加密；回答使用独立生成模型并逐次确认云端片段出站。

| 项目 | 云端知识库 | 客户端本地知识库 |
| --- | --- | --- |
| 使用入口 | 现有知识库入口 | 用户主动添加/启用后出现独立本地库 |
| 文档处理与检索 | 现有服务端处理链、权限、PostgreSQL/pgvector | 用户设备上解析、分块、向量化、存储和检索 |
| 向量模型 | 继续由当前服务端配置管理 | 默认 `Xenova/multilingual-e5-small`，可单独配置其他兼容模型 |
| 模型下载 | 现有服务端部署规则 | 默认安装和首次启动不下载；用户明确启用本地库后才按需安装所需资源 |
| 配置和索引 | 保留现有配置、文档与索引 | 独立配置、独立索引空间；不写云端 `document_chunks` |
| 故障处理 | 现有服务端策略 | 展示本地错误与重试，不自动调用云端 embedding 或上传本地文档 |
| 模型切换 | 由云端部署管理 | 只影响选定本地库，重建对应本地索引 |

这里的“本地模型”指客户端知识库的向量模型，不是工作台聊天用的 Ollama/LM Studio 模型。现有服务端 `LOCAL_EMBEDDING_ENABLED` 指服务器自身运行的历史兜底，不是客户端开关。本次不修改其行为或将其替换成 E5；其模型空间兼容性需单独审查。

## 默认模型

| 字段 | 默认约定 |
| --- | --- |
| 原模型 | `intfloat/multilingual-e5-small` |
| ONNX 仓库 | `Xenova/multilingual-e5-small` |
| 量化 | 首版 Transformers.js 3.8.1 q8，实际加载 model_quantized.onnx；固定 revision 与 SHA-256 见实现说明 |
| 向量维度 | 384 |
| 单次输入上限 | 512 tokens，包含前缀与特殊 token，按 tokenizer 计算 |
| 查询前缀 | `query: `，非英文也必须使用 |
| 文档片段前缀 | `passage: `，非英文也必须使用 |
| Pooling | 按 attention mask 排除 padding 的 mean pooling |
| 归一化 | L2 |
| 默认运行目标 | 已实现并验证 Worker + ONNX Runtime WASM 单线程 CPU；8 GB 低配验收仍待执行 |

2026-09-17 历史核验的 `onnx/model_int8.onnx` 为 118,054,593 字节，约 118 MB（112.6 MiB）。2026-09-20 首版已实测 Transformers.js 3.8.1 使用 `model_quantized.onnx`（118,308,185 字节）；加 tokenizer 与配置合计约 129.1 MiB，运行时与索引另计。完整 revision/哈希见首版实现说明。

## 用户主动启用流程（首版已实现核心路径，目录导入及回答生成待做）

1. 默认只提供“添加本地知识库”的入口，不下载权重、不加载推理运行时、不创建文档索引，也不扫描本机目录。
2. 用户选择启用后，展示默认模型、预计下载和磁盘需求、保存位置；可切换自定义配置。首次下载资源需联网，已缓存模型的后续检索应可离线。
3. 用户确认安装后才开始下载；支持进度、失败重试、取消、资源完整性校验。取消/失败不能标记为可用或触发静默云端降级。
4. 模型可用后，用户选择需要导入的文件/目录；仅处理明确选定的材料，导入与索引显示状态。
5. 本地检索结果包含文件/片段来源；回答生成模型另行选择。使用云端聊天模型时，用户应明确允许将相关本地片段发送给它；本地向量化不等于整条问答链离线。
6. 关闭本地库后停止后台索引和推理；删除知识库和删除共享模型缓存是不同操作，需明确各自影响。正在使用的模型缓存不能直接移除。

## 自定义向量模型（首版公开单文件 ONNX；完整适配范围见实现说明）

每个本地库保存独立的 embedding profile，不复用聊天模型 profile。首版已实现兼容的公开 ONNX 仓库；本地模型包、Ollama 或其他本机 `/embeddings` 接口仍待扩展评估。远程 embedding API 不应作为本地模式的隐式后备。

配置至少需要模型来源/标识、固定版本或文件哈希、权重/量化格式、tokenizer、维度、最大输入 tokens、pooling、归一化、查询/文档前缀。采用预设填入常用模型参数，允许高级用户修改；未验证的模型先执行兼容性测试，再允许索引。

需要校验输出形状、实际维度、有限数值、tokenizer 与权重匹配、query/document 编码方式。E5 与 BGE 的前缀和 pooling 不同；相同向量维度也不意味着能够混用。不支持的 ONNX 算子/架构应明确报错，不能靠截断或补零冒充兼容。无需运行下载模型包里的任意 Python/JavaScript 代码。

## 数据与性能约束

- 本地库标识与云端库标识分离。文档、缓存、索引任务和检索入口均携带明确作用域，不靠同名文件判断归属。
- 索引元数据记录模型指纹：模型及版本、文件哈希、量化、tokenizer、维度、pooling、归一化、前缀及切块规则。文档和查询必须匹配同一指纹。
- 修改模型参数时建立新索引版本，成功后切换；旧索引在重建失败时仍可保留。只重建本地库，不要求云端重建或迁移。
- 将分块/推理放入后台 Worker 或受限本机任务，不阻塞聊天 UI；限制并发、小批量、增量处理，支持取消。首版文件读取使用异步读取；已支持复用已完成文档索引，未提交任务的断点续建仍待实现。
- 默认 384 维 float32 原始向量每条 1,536 字节，1 万条约 15.36 MB；文本、索引结构、元数据和模型缓存另算。
- 客户端知识库存储不直接塞进现有会话 localStorage。首版使用独立 IndexedDB/Cache Storage；聊天密钥继续本机加密，本地知识库原文和索引当前未加密，并在界面说明。可选知识库加密/导出备份仍待实现。

## 验收要求（首版功能验证已执行；性能/检索质量基准仍待执行）

- 全新安装、仅用云端库、只配置聊天模型时，不发生本地 embedding 下载/初始化。
- 主动启用后才安装 E5；下载取消、离线首次启动、空间不足或文件损坏可恢复，不留下假就绪状态。
- 在普通 8 GB 内存、无独显设备测量下载总量、冷启动、峰值内存、每百段索引耗时、查询 P50/P95 和 UI 响应；不先承诺低配速度。
- 禁网情况下，已缓存模型仍能解析首期支持格式并检索本地库；生成回答是否离线另行验证。
- 切换本地模型、删除/重建本地库、运行本地与云端并行查询时，云端模型与索引保持独立。
- 自定义模型不匹配、错误维度、错误前缀/pooling 配置时拒绝使用旧索引，提供重新建索引路径。
- 用中英混合实际业务样本评估 Recall@5 和引用正确性，验证 E5 的 query:/passage: 与 mean pooling 实现。
