# 云端向量离线迁移与回退

更改 `EMBEDDING_DIMENSION` 或运行 Alembic 不会把已有向量转换成新模型的向量。同维度更换模型也必须重新生成。`python -m app.ops.embedding_migration` 提供现有分块的离线重建、事务切换与回退；只作用于云端 PostgreSQL，不接触客户端本地 E5 索引。

## 前置条件

先创建并验证数据库、上传文件和运行配置的联合备份，参考 [联合恢复](JOINT_RECOVERY_BUNDLE.md)。在**从备份恢复的隔离副本**上先演练，下述命令从后端工作目录或维护容器 `/app` 执行。`DATABASE_URL` 指向明确选定的副本；连接信息只通过进程环境或受保护 `.env` 注入，不放入命令行或报告。

停止 API、Celery worker、beat、清理/运维调度及所有其他写入者。工具不会停止这些服务；`--writers-stopped` 是操作者对已停写的确认。准备阶段持有文档/分块表共享锁，切换和回退阶段持有排他锁，并与现有运维工具共用维护互斥锁。别在 API 仍接收请求时运行它；阻塞应用请求不等于合适的停写编排。

配置目标主 Embedding 的模型、端点、密钥、`EMBEDDING_DIMENSION` 和按需的 `EMBEDDING_SUPPORTS_DIMENSIONS`。`providers.yaml` 的主 Embedding 维度必须与 `EMBEDDING_DIMENSION` 一致。工具只使用这一个主端点，不调用备用模型、Redis、重排、聊天或邮件，不下载本地模型；准备阶段会把**现有可检索状态（completed/low_quality）且未删除文档的分块正文**发送给该供应商并产生用量。先核实资料处理授权、供应商区域、费用及额度。

准备使用有界游标逐条处理，目标维度支持 1–2000（对应现有 vector 索引能力）。数据库需要能同时容纳旧向量、新向量和索引重建的空间；工具不提供磁盘容量估算、供应商批量配额管理或自动续传。单次 SQL 的上限沿用 `DB_OPERATION_TIMEOUT_SECONDS`；大库应在副本上测量锁等待、临时空间和停机时长后确定安排。

## 执行

先检查实际列维度、分块数和已留存的迁移状态；此命令只读且不请求供应商：

```sh
python -m app.ops.embedding_migration inspect
```

准备目标向量，不更改当前分块、维度或索引：

```sh
python -m app.ops.embedding_migration prepare --writers-stopped
```

成功输出 JSON，记录其 `run_id`（32 位十六进制），以及 `chunks`、`indexed`。只有 `completed/low_quality`、未删除文档的分块会生成新向量；失败、处理中、已删除文档的分块在激活后向量和空间标记为空，正文/状态保留。它们后续可按应用流程重处理。活动分块为空、向量维度不符、非有限数值、零向量、请求失败等都会使整个准备事务回滚，不保留半成品；失败后检查数据库状态与供应商用量再决定重试，已消费的请求不会自动退款或去重。

准备输出中的数量不表示切换或语义质量验收已完成。激活前保持停写，用上一步真实的 ID 替换 `RUN_ID`：

```sh
python -m app.ops.embedding_migration activate --run-id RUN_ID --writers-stopped
```

激活前重新核对分块/关联文档的完整快照摘要及暂存向量摘要。正文、元数据、状态、权限、分块数量或向量变化会拒绝激活，不能覆盖更新后的数据。激活在一个事务中转换列维度、写入新向量及与生产入库相同的模型空间指纹，按实际定义重建引用该向量列的索引，并执行 ANALYZE。索引/SQL 失败会回滚列、向量和索引变更。工具不会截断或填充旧向量来充当新模型向量。

保留旧向量期间只允许一个 prepared/active 迁移。此时先以只读方式核验列维度、索引、不同账号的资料权限、检索来源和真实问答；避免启动会写入文档或修改状态/权限的应用链路，以保留精确回退窗口。快照摘要不替代有证据金标的语义质量评估。

## 回退与清理

若保持停写且数据未变化，可精确恢复原维度、每个分块原向量与空间标记：

```sh
python -m app.ops.embedding_migration rollback --run-id RUN_ID --writers-stopped
```

回退同样重建实际索引并校验还原后的完整快照摘要。之后将运行配置恢复为旧模型/维度，核验通过后再启动服务。工具不会替你修改配置或执行部署切换。

**恢复写入后，旧向量回退不再是通用回滚方案。** 一旦分块或关联文档变化，回退会拒绝覆盖新数据；须按联合备份恢复/另行迁移计划处理。不要手工修改 manifest 或暂存表来绕过校验。

副本演练结束、准备结果不再需要，或新模型验收并明确放弃该次回退窗口后，显式删除暂存旧/新向量：

```sh
python -m app.ops.embedding_migration discard --run-id RUN_ID --writers-stopped --discard-rollback
```

该命令只删该次暂存表，保留无正文/密钥的计数、模型空间摘要和状态；不删除业务资料。暂存表含旧/新向量，应遵守与数据库备份相同的权限和保留策略。discard 后不能通过该 ID 再回退，也不会改变当前活动向量。之后核实服务配置与列维度一致，再启动服务。

本机隔离 PostgreSQL/pgvector 的合成回归不证明用户目标库或生产迁移完成；目标环境的容量、停写、Secret/卷、RPO/RTO、部署回滚和业务质量仍需单独验收。所有测试容器/镜像应在演练后仅按本轮资源清单清理，不执行全局 prune。
