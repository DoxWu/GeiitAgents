# 工作台加密存储与迁移

更新：2026-10-01，开发版 dev.39。此处是客户端工作台存储；本地知识库原文、向量与模型缓存仍分别管理，云端数据库未改动。

## 当前实现

工作台密文改存 IndexedDB 数据库 `geiit-private-vault-v1` 的 `vaults` 对象仓库，键仍为 `geiit.workbench.encrypted.v1`。只有 AES-GCM 加密信封进入持久存储；口令、派生密钥和解密后的工作台仍留在内存。加密算法与 `.geiitwork` 备份格式未变，没有新增运行依赖。

读取优先使用 IndexedDB；没有对应密文时兼容读取旧 localStorage 密文。解锁旧库本身不迁移，第一次成功保存或恢复提交后才把新密文写入 IndexedDB，并用 `geiit-indexeddb-v1:` 标记替换旧 localStorage 副本。写入失败不清理旧密文。标记写入失败也不撤销已经成功的 IndexedDB 保存，新客户端仍优先读取已提交密文。

需要使用 dev.39 或更新客户端继续访问迁移后的同一开发数据目录。旧客户端不认识标记，也不读取 IndexedDB；不要同时运行旧版本或将其视为可用降级。跨设备迁移仍使用工作台加密备份，不复制浏览器数据库文件。

## 并发、取消与失败

- 加密在事务外进行。保存与整库恢复共用短时 Web Lock，并在 IndexedDB 读写事务内再次比较完整旧密文；即使没有 Web Locks，两个新客户端也不能同时成功覆盖同一个旧值。
- 事务内写入前再检查锁定或取消状态。恢复预检查从第一次异步读取前就占用传输状态，取消后不发布过期预览。已提交的事务不会因后来取消而回滚。
- BroadcastChannel 通知其他窗口锁定内存密钥库，忽略自身来源；原有 storage 事件仍处理旧窗口变化。通知不可用时事务比较仍保护后续写入，但不能保证立即清理另一窗口的旧内存。
- 同步 `put` 异常和事务中止都进入存储错误路径，保留旧密文；笔记导入、文本编辑和备份恢复可以只重试持久保存，不重放模型或文件写入。
- 浏览器没有 IndexedDB API 时保留 localStorage 兼容存储；IndexedDB 存在但打开失败时不静默切回旧副本。两条路径容量不同。

## 容量与验证边界

密钥库仍整体加载、序列化、加密并写入。明文快照上限为 16 MiB，备份文件上限为 24 MiB；IndexedDB 消除了常见 localStorage 单值配额瓶颈，不能消除磁盘不足、浏览器清理、整库内存峰值或正文编码的字节开销。500 条正式记录、100 条草稿和单条 20000 字符均是各自上限，不保证这些限制在任意文本组合下都能同时达到。

本批定向回归覆盖旧密文迁移、6 MiB 正文加密往返、同时创建/旧值冲突、事务内取消、同步写入异常、锁库恢复、备份替换冲突、通知来源隔离、标记配额故障和异步预检查取消。生产浏览器验收覆盖实际备份下载/独立解密、IndexedDB 故障重试、另一窗口冲突、个人 JSON 导入、单文件及批量文本编辑和历史导航。最终次数、容量实验和安装包校验值见 [工作记录](WORK_LOG.md)。

`frontend/scripts/vault-qa.mjs` 为验收脚本提供真实密文读写和 IndexedDB 故障注入；不得把 localStorage 标记当作密文做保密性或恢复断言。`verify-vault-capacity.mjs` 仅在独立合成 Chromium 数据目录内做最大记录/草稿正文与进程终止实验。开发机结果不代表 8 GB 设备、物理断电、Windows WebView2、安装升级或生产部署验收。
