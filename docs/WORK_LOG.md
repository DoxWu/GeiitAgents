## 注意事项与已发现的坑

| 问题 | 实际影响 / 处理原则 |
| --- | --- |
| 自动迁移不是数据恢复 | 没有备份不能找回账号和历史文档；接口拒绝覆盖已有数据，实际持久化问题留待后续部署阶段核实 |
| 同平台监控也会一起停 | Sealos 整体故障需外部监控；外部监控自身也需要独立可用性观察 |
| 备份环境限制 | 托管库可能没有 CREATEDB/pgvector；pg_dump 版本不能低于源库；密钥丢失无法还原 |
| PostgreSQL dump 不含文件字节 | uploads/对象存储、Redis 与配置需各自备份；定时 dump 不是主从切换/PITR |
| 空库判断要保守 | 只恢复真正空库；部分表损坏不可自动清空覆盖；错误密钥/过期备份必须拒绝 |
| 默认本地模型体积 | E5 单个 INT8 ONNX 约 118 MB，不含运行时/tokenizer；不是此前 BGE 的 24 MB，不应默认随安装包捆绑 |
| 向量空间不兼容 | 同维度也不能混用；模型、前缀、pooling 或切块规则变化必须重建相应本地索引 |
| 名称容易混淆 | 客户端向量模型、聊天模型和服务端 LOCAL_EMBEDDING 是三个独立概念，不复用同一开关 |
| 现有服务端兜底 | 历史 BGE 兜底与云端向量空间兼容性需要另行审查，本轮未调整或声称已解决 |
| 本地检索不等于本地回答 | 云端聊天模型会收到用于回答的片段；需要用户明确选择，不默默上传 |
| 模型兼容性 | 不能只填模型名；ONNX 架构/量化/tokenizer/pooling 均需适配，不执行任意下载脚本 |
| 模型目录不是能力声明 | 目录可能包含向量模型，接口也可能不提供目录；保留手填，工具/图片/上下文能力显示未知。文本测试需真实请求，可能计费；状态只对当前表单有效 |
| 列表与密钥端点绑定 | 获取草稿列表也必须防止已保存 Key 随新 URL 发往别处；主动重新填 Key 或清除后才允许。列表失败不能静默切换或阻止手填保存 |
| Tauri Channel 入参 | 当前版本 Channel 是专门的 command 参数，不能直接包成 Option<Channel> 走普通反序列化；使用独立流式命令，保留原非流式命令和权限注册 |
| 文本增量不等于完整回答 | 工作台四路径现在要求上游 DONE/finish_reason，转发前端还要求内容一致的 done；达到 length/filter 可保留非空回答但标注可能不完整。只有客户端升级不能修复旧后端把上游 EOF 包成 done 的问题，需匹配更新前后端 |
| SDK 文本封装丢弃结束元数据 | 账号工作台新增严格 HTTP 方法复用选中模型/Key/temperature，保留原知识库 SDK 路径不变；工作台无隐式重试，中断不改用别的模型。非流式账号接口尚未获得此验收，专有客户端需明确实现适配 |
| 四位解锁口令 | 只是本地解锁最低长度，不是 API Key 长度；加密不等于能抵御弱口令离线猜测；口令丢失当前不可恢复 |
| 客户端关闭或锁定 | 云端没有用户 Key 可继续调用；后续任务需 waiting_device，不能伪称后台持续运行 |
| 客户端缓存 | dev.39 工作台密文在独立 IndexedDB，旧 localStorage 在首次保存后只留标记；本地知识库为另一 IndexedDB + 模型 Cache Storage，原文未加密。同一 origin/客户端数据目录账号共享本机数据，不同 origin 不共享；迁移后不要同时使用旧客户端 |
| 前端环境与桌面跨域 | 桌面构建需正确 VITE_API_BASE_URL，后端 CORS 需桌面 origin；切勿把 Key 放 VITE_* |
| Windows 测试环境 | Python DEBUG 环境曾为非法值 release；测试设置进程级 DEBUG=true；pytest 默认临时目录权限失败需工作区 basetemp |
| 源码/二进制对应 | 最新为 dev.64 未签名安装包，9,168,467 字节，校验值见当前状态；系统 PATH 无全局 Cargo，仓库 `.tools` 回退/会话脚本可用。Word 两份样本分页已验，安装升级/跨物理卷未验；重建相同版本的安装包也可能改变字节和摘要 |
| 分页与容量不同 | 历史只渲染当前页/展开详情，但密钥库仍整库加载和加密；筛选批次必须保留全组，不能把当前页或搜索命中子集当作整条记录的撤销/恢复/导出范围 |
| 批次部分完成与恢复 | 批量写入不是事务；失败停止后续文件，未执行保持 not-started，存储重试不重放文件操作。恢复只接受当前身份/摘要仍匹配批次写入版本的文件；含批次字段的备份需 dev.18+，旧版不支持降级保留 |
| 流式预览与成果摘要 | 预览只保留前 16000 个 UTF-16 单元、60 ms 合并更新，不持久保存；最终成果仍完整校验。非 stop 文档导出附状态说明，下载 Markdown/HTML 字节不等于原始成果摘要；DOCX 有独立字节摘要。手动编辑的新版本不继承供应商原因，恢复旧版本则保留 |
| 工作流保存与中断 | 页面修改需点击保存才进入密钥库；布局不是执行顺序。运行固定修订与输入快照，锁库恢复只恢复记录，不自动续跑。非 stop 模型成果保留但中止后续步骤；复制历史是新运行，可能再次计费 |
| 工具回复的空正文与附加元数据 | LangChain 转换要求工具调用消息保留 content 键；供应商可能增加 call 元数据，响应只取白名单字段，请求仍严格校验；本批通过真实请求发现并修复 |
| SDK 隐式重试与主测试 mock | 账号工具实例设置 max_retries=0，避免超出任务轮次；旧测试在收集阶段注入 LangChain mock，真实 SDK 测试需单独进程与隔离依赖，跳过不能记为通过 |
| HTTP 恢复与 CLI 目标不同 | HTTP 使用 RESTORE_TARGET_DATABASE_URL 的独立空库；直接 CLI restore 使用 DATABASE_URL，均不会清空已有库 |
| 执行中断的不确定结果 | 恢复可能成功但状态没写回；任务标记 interrupted，不能自动重放，先核查目标 |
| 文件整理不是 OS 原子重命名 | 浏览器没有排他创建/条件删除；操作期间勿外部编辑。复制/删除可能改变修改时间和其他元数据，预留约两倍批次大小的额外磁盘空间及 writer 临时空间 |
| 整理源删除后的旧 File 快照 | 可能无法再次读取；恢复必须重新读取暂存。恢复失败时保留目标/暂存，不清理最后可恢复副本 |
| 文件已完成但本机保存失败 | 保留内存完成状态，仅重试加密保存，不重放文件操作；重开先核验。锁定后补偿未结束时重新解锁也不能启动另一操作 |
| 文本写入与断电 | 原生以同一锁定句柄写入并尝试故障回滚，不是原子替换/断电事务；回滚失败、缺失文件或无效 UTF-8 时保留现场并明文导出历史供人工恢复。已发出的 Rust 写入可能在锁库后完成 |
| 文本草稿/版本容量与身份 | 每库一个草稿、50 条版本/2 MiB 文本，不自动淘汰；与其他集合共用 16 MiB 明文上限和 IndexedDB 配额。浏览器刷新后没有目录/文件身份凭证，需显式确认且无法阻止最后检查后的外部写入；原生身份摘要可持久比较但授权 token 不入库 |
| 暂停提醒不能撤回正在发送的邮件 | 已进入供应商请求的投递仍可能 sent；unknown 需明确重试或人工结束，人工结束记录保留“可能已发送”，不伪造发送成功/失败 |
| 修改提醒规则与时区 | 需同时明确未来的下一次时间并重设重复锚点；不能只改规则后沿用陈旧锚点。表单使用记录自身时区，夏令时不存在/重复时刻需显式处理 |
| 提醒提交网络失败或修订冲突 | 原修改可能已提交；新实现把完整请求/修订号先加密保存，刷新后核查或重试同一提交。创建查询 404 不证明未执行；编辑匹配只能证明当前内容一致，不证明具体哪次请求写入 |
| 草稿自动保存与表单加载 | 本机笔记表单停顿 400 毫秒保存；工作流定义停顿 500 毫秒保存。排队写入会在锁库时冲刷，突然断电或进程被强杀仍可能丢失未完成写入。QA 出现过两次初始/恢复表单禁用超时，加入诊断后连续三次通过，尚未定位根因；再次复现需记录 capability/list 返回与 busy 状态 |
| 本机草稿与正式记录写入失败 | 提交先保存原始草稿，再写正式记录并移除该草稿；最后写入失败保留内存结果，只重试存储。归档恢复失败也要同步编辑器的修订号，避免重试后误报冲突 |
| 本机记录的容量与导出 | 100 草稿/500 正式记录是数量上限，不保证所有字符组合都满足 16 MiB UTF-8 整库上限；IndexedDB 也受磁盘/浏览器配额影响。满草稿不淘汰旧编辑，Markdown/JSON 是明文；失败只重试持久化，完整迁移使用 `.geiitwork` 加密备份 |
