# 授权目录内的文本编辑与版本恢复

更新：2026-09-29。对应开发分支与 dev.13 本地验证包；没有推送、安装升级或部署。

## 已实现的用户流程

工作台“文件整理 → 文本内容编辑”支持用户主动选择目录，再选中一个可见 MD/TXT 文件读取。只读取单个文件，不递归目录，不调用模型或上传文本。首版限制为 **UTF-8、256 KiB**，拒绝无效编码、二进制控制字符和未配对代理字符，不进行有损转码。

1. 读取原文并计算 SHA-256，创建独立加密草稿。每个本机密钥库保留一个文本草稿；读取其他文件前必须完成或明确丢弃当前草稿。
2. 编辑内容和写入换行格式。原文件的 UTF-8 BOM 保留，统一 LF/CRLF/CR 沿用原格式；混合换行文件在修改内容后必须明确选择输出格式。历史原文恢复按确切字节保留混合换行。
3. 点击“预览文本差异”。预览显示原文/写入版的字节数、BOM、换行与末尾换行信息，以及完整文本。修改任何内容会使旧预览失效。
4. 确认写入后先持久保存原文和新文，再复核目录、文件身份及摘要，最后写入并校验。当前文件被外部修改时拒绝覆盖，保留草稿供明文导出或人工合并。
5. 在历史中重新选择目录并核验；“预览恢复此记录原文”会读取当前文件，与历史原文对比，用户确认后新增记录。恢复操作也保存被替换的当前内容，不删除旧历史。

逐行比较复用有界差异算法，超过 400,000 合计字符或 10,000 合计行时不计算逐行差异；LCS 超出预算时用整段比较。界面最多呈现 400 条差异行，明确提示截断，并保留两份完整文本和明文导出。不能把截断的逐行视图称为完整差异。

## 授权和文件写入边界

| 项目 | Windows 原生 | 支持 File System Access 的浏览器 |
| --- | --- | --- |
| 目录授权 | 系统选择器，Rust 保管路径，临时 token | 用户目录选择器，内存句柄 |
| 文件定位 | 授权 token、平面文件名、身份摘要 | 已选目录内文件句柄 |
| 身份检查 | 目录/文件的卷、ID、创建时间摘要 | 同一页面会话保留句柄检查 isSameEntry；刷新后无法恢复身份凭证 |
| 摘要检查 | 同一个禁止外部写入/删除的打开句柄复核 | 写入前、持久记录后、writer.close 前再次读取核验 |
| 写入失败 | 在同一个句柄上尝试恢复原文并再次核验 | abort writer，不再 close；原文和预期新文保留在加密历史 |
| 并发限制 | 单次原生操作有文件/祖先目录句柄锁；不保证整段用户编辑时间排他 | 没有外部进程 CAS，最后核验到提交间仍有竞态 |

原生新增 `organizer_access` 的 `read_text` / `write_text` 操作，继续拒绝任意路径、路径分隔符、ADS、设备名、链接/硬链接和未知字段；扩展名、UTF-8、字节大小、文件身份与摘要也在 Rust 检查，不能仅依赖界面校验。没有新增通用文件系统权限或模型工具权限。

原生文本编辑明确允许最多 256 KiB 内容通过 IPC；原有文件移动/复制/摘要仍使用 Rust 64 KiB 缓冲区，不通过全文件 IPC。文本写入采用原地 seek/write/set_len/sync_all/摘要校验，保留文件身份，**不是原子替换或断电事务**；其他读取者可能看到写入中的短暂内容。回滚也可能失败，此时保留文件和加密快照，要求人工导出恢复。Windows 文件属性/时间等元数据不保证保持原值。

文本读写与移动/撤销共享 `geiit-file-organizer` Web Lock 和进程锁。共享锁独立成小模块，移动/补偿引擎仍按需加载。离开页面释放界面目录引用，在途操作单独持有引用。锁库能阻止未发出的写入；已经发给 Rust 的受限写入可能完成，不能把锁库称为已撤销。旧操作完全结束前，即使重新解锁也不能开始另一文件操作。

浏览器恢复草稿或核验历史前要求明确确认目录正确。显示名不能验证身份；浏览器同源 Web Locks 无法约束外部编辑器或其他浏览器。操作期间应避免外部编辑。

## 加密草稿和执行记录

- `VaultData.fileEditDraft`：原文、摘要、文件名、目录显示名/原生身份、编辑内容、换行/BOM 设置、编辑修订及可选恢复来源。无绝对路径、临时 token 或持久目录权限。
- `VaultData.fileEditVersions`：每次写入的前后确切文本及摘要、身份、目录/文件显示名、来源草稿、状态、时间、可选恢复来源/核验结果。与不保存内容的整理记录独立。
- 沿用本机 AES-GCM 密钥库；不按云端登录账号分库。400 ms 合并草稿保存；切换模块保留内存草稿，手动锁定将尚未保存的草稿排队冲刷，刷新恢复最后成功密文。存储失败/强制退出仍可能丢失尚未持久化的输入。
- 最多 50 条版本、前后文本合计 2 MiB，无自动淘汰。整库 localStorage 可能更早耗尽配额，配额失败时不进入文件写入。未核验的历史禁止删除，原文和新文均可明文导出。

| 状态 | 含义 |
| --- | --- |
| running | 前后快照已登记，写入进行中；重开转 interrupted |
| succeeded | 写入后校验成功，或中断后核验当前文件与新文一致；不是永久当前状态证明 |
| not-applied | 中断/异常记录核验为原文；允许重新预览执行 |
| interrupted / needs-attention | 结果未确认；保留快照，先核验，不自动重放 |

核验只读比较原文/新文/当前身份与摘要，记录时间；已完成记录不会因为后来编辑而被改写成“从未执行”。缺失文件、无效 UTF-8、超过上限或权限错误时核验失败，原历史保持。恢复原文需要当前文件可读取并可预览；严重损坏或文件丢失时可导出历史文本人工恢复，当前没有自动重建缺失文件。

最终记录保存失败时，内存仍保留完成结果并移除已提交草稿；“重试本机保存”仅写密钥库，绝不重复磁盘写入。若此时强制退出，下次可能看到旧 running 转 interrupted 与旧草稿，必须先核验。即使核验为新文，旧草稿也不自动丢弃，避免误删用户输入。
