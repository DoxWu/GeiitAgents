# 本机笔记与待办 JSON 导入

更新：2026-09-29。dev.17 增加“笔记与待办 → 导入 JSON”。按需加载页面和校验模块，没有新增运行依赖、服务端接口、模型调用或邮件投递。导入只处理当前解锁的本机加密库；云端提醒与本地向量知识库不参与。

## 文件与预检查

- 支持现有正式记录导出：`{ format: "geiit.personal-records", version: 1, exportedAt, items }`，以及“导出当前草稿”产生的单个原始草稿 JSON。
- 仅接受非空、最多 16 MiB 的 UTF-8 JSON；正式记录文件包含 1–500 条。严格检查字段白名单、类型、标识、修订、标准 UTC 日期、完成/归档状态及时间顺序。重复标识、未知字段、未规范化的正式标题/标签或任何无效行会拒绝整份文件。
- 草稿可以包含空标题、重复的原始标签输入和未完成截止时间文本；保留固定 IANA 时区。正式字段与原始编辑字段分开验证，允许当前客户端草稿导出所含的正式记录元数据。
- 预检查不修改记录。界面每页 20 条，支持逐条处理、全部跳过与恢复默认选择；翻页保留选择，变更选择清除确认勾选。比较内容按纯文本展示，不执行 HTML、不加载 Markdown 外部图片。
- `exportedAt` 和文件修订号不代表可信的版本优先级，不根据不同设备的修订大小自动覆盖。

## 处理规则

| 情况 | 默认 | 可选行为 |
| --- | --- | --- |
| 新标识、新内容 | 新增 | 新增或跳过 |
| 同一标识，内容和状态一致 | 跳过 | 跳过或另存副本 |
| 不同标识但内容与状态一致（包括文件内前面的新条目） | 跳过 | 跳过或保留原标识新增 |
| 同一标识、同类型，内容/状态不同 | 跳过 | 跳过、另存副本、明确替换 |
| 同一标识有本机编辑草稿，或正式类型不同 | 跳过 | 跳过或另存副本，不覆盖本机编辑 |
| 单个草稿 JSON | 恢复为新草稿；内容已存在则跳过 | 跳过或恢复为独立新草稿 |

同内容比较包含类型、标题、正文、标签顺序、待办状态/优先级/截止/完成时间和归档时间；忽略修订、创建时间与更新时间。不同标识的重复内容提示不意味着它们是同一业务记录，用户可以选择保留。

新增正式记录保留来源标识和元数据；另存副本分配新标识、修订 1，保留来源日期及状态。替换保留本机标识、创建时间，将本机修订加 1，其余内容/完成/归档状态取文件版本；更新时间取当前时间、本机更新时间、文件更新时间的最大值，避免设备时钟偏差导致时间倒序。修订到达 1,000,000 的记录只能跳过或另存。替换归档记录可以同时改变归档状态，确认界面明确提示。

草稿导入从不替换旧草稿或自动提交正式记录：分配新记录/编辑标识、基础修订 0，移除嵌入的正式记录元数据，保留原始输入、标签文本、截止文本与时区。恢复后仍需在编辑器中完善并保存。

## 确认、冲突与保存失败

- 确认前对当前全部正式记录和草稿进行完整值比较；预检查后任何变化（即使修订未变）都会使确认失效，需重新选择文件预检查。选择集合必须与预检查完整匹配。
- 先计算整个批次，再一次更新内存集合。导入后超过 500 条正式记录或 100 条草稿，整批不修改；归档和已有内容也占配额。
- 提交在写入前消费预检查，不能重复提交。写入沿用整个密钥库的加密快照和跨窗口密文冲突保护，其他窗口变更不会静默覆盖。
- 写入失败保留已应用的内存结果，显示“尚未确认持久保存”。“重试保存导入结果”只重新持久化当前快照，不再次新增副本、替换或增加修订。确认保存前禁止新的导入预检查。
- 预检查、来源文件和处理结果提示不入库。取消读取、离页、锁库会清除预检查，迟到读取不回填。已开始的加密写入可能在离页后完成；重新进入后可再次确认保存结果。
- 数量上限不等于存储容量承诺。整体 localStorage 可能更早耗尽；若无法保存，可用工作台加密备份保护当前内存。刷新/关闭/锁库后只能读取最后成功写入的快照，不能把内存应用成功当作已持久保存。

JSON 文件是**明文**，导入后的本机保存才使用现有加密库。完整工作台迁移仍使用 [.geiitwork 加密备份](WORKBENCH_BACKUP.md)；本入口不是整库替换或自动多设备合并。Markdown 导入、字段级合并、第三方待办格式、批量草稿文件、后台同步和容量/低内存/突然断电验收尚未实现。
