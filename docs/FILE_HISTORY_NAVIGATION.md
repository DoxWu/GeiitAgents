# 文件历史分页与检索

更新：2026-09-29，dev.19。文件整理、文本版本、文本批次三个历史面板分别提供搜索、状态筛选和每页 10 条导航，无新增运行依赖、后端接口或存储字段。

## 查找和翻页

- 搜索仅针对文件名、目录显示名、记录/批次编号及恢复/撤销来源；整理记录还可查找源文件名、目标文件名、暂存名称。不索引或上传文件正文。
- 查询去除首尾空白、按 NFC 规范化并忽略大小写，使用字面包含匹配，不使用正则。搜索范围包含全部本机历史，不限当前页。
- 搜索和状态同时满足才命中；批次必须由同一个成员同时满足两个条件。命中后仍展示该批次全部保留记录，核验、恢复和导出继续使用完整分组，不截断成搜索结果。
- 按创建时间倒序，同一时间用记录编号确定稳定顺序；批次内部按原 index 顺序展示。不会修改存储中的数组顺序或重编号批次。
- 筛选变化回到第一页；删除最后一页全部记录时回退到仍存在的页，后续新增不会跳回已消失页。首页/上一页/下一页/末页均有边界禁用；文件操作期间禁用历史筛选与顶层翻页。
- 筛选和页码仅在当前面板存活期间保留，切换页签、锁库或刷新后重置；不会写密钥库、加密备份或 URL。

## 渲染与操作边界

- 只挂载当前页最多 10 个历史条目；默认折叠，展开才挂载详情和操作按钮，关闭后卸载详情。
- 整理/移动记录中的文件明细每组最多 50 个；历史记录总共最多 500 文件的既有限制不变。翻页不会缩小“核验目录”“预览撤销”“导出记录”的操作范围。
- 文本版本恢复继续按被点击记录的稳定 ID 读取原文；切换历史页或搜索不会丢弃当前文本编辑草稿。删除仍要求确认并走既有状态保护及加密持久化。
- 批次可在删除部分历史后显示“保留数/原始总数”；缺少条目不自动补齐、重放或删除同批其他版本。

分页减少 DOM 和展开详情的渲染成本，**不减少整库解密或持久化的数据量**，不增加配额。原有整理 100 条、文本 50 条/前后文本合计 2 MiB 限制不变，localStorage 仍可能提前耗尽。展开后变更清单/撤销预览仍可能显示完整 500 行；自动合并冲突、历史归档和移动后关联文本历史仍待做。

## 验证

- 新增域/UI 回归覆盖稳定排序与 NFC 查询、不搜索正文、后页筛选、删除末页回退、后页恢复 ID 与草稿保持、部分批次全组恢复、500 文件明细分页且撤销仍完整。
- `frontend/scripts/verify-file-history.mjs` 默认检查生产 Web，`--native` 检查最终开发 exe；使用独立加密合成数据和实际下载文件，不调用模型、不发送邮件、不授权外部目录。
- 合成数据为 100 条整理记录、50 条文本版本、25 个批次，最长明细 500 文件，初始密文 1,283,407 字节。验证隐藏详情不挂载、跨页搜索、完整 JSON/原文导出、只读操作密文不变、明确删除后的独立解密以及刷新后保留部分批次；Web 另验 390px。
- 上述是当前开发机上的条数边界与导航验收，不是最大正文容量、低配性能、强杀/断电或外部文件写入重验。最新实际结果和构建状态见 [工作记录](WORK_LOG.md)。
