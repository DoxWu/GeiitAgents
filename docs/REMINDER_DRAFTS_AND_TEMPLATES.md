# 提醒草稿、模板与搜索

更新：2026-09-29。本批为应用代码和本机验证，未部署；没有发送邮件。

## 草稿与提交恢复

工作台 → 笔记与待办 → 邮件提醒。每个服务端地址、账号 ID 和账号邮箱的组合保留一个当前提醒草稿，与其他账号分开。新建输入、编辑原记录的修订号、时区、夏令时重复时刻选择及恢复选项都写入原有本机 AES-GCM 密钥库。

输入停止 400 毫秒后合并保存；页面明确显示“正在保存”“已加密保存”或失败。可手动保存草稿，锁库会先将当前草稿加入保存队列，刷新解锁恢复最后成功写入的版本。离开任务视图不丢弃已保存草稿；离开页面时若还有未完成写入或存储错误，浏览器会给出离开提示。强制退出、存储写入失败或忽略提示，仍可能丢失未完成写入的最后一段输入。

点击保存提醒时先生成完整提交快照，并要求加密保存成功，才发 HTTP。创建快照包含不可变的 `request_id` 和完整原始请求；编辑快照包含原记录 ID、原修订号和修改字段。保存失败不发网络请求。未知结果、关闭页面或账号切换后，快照保留；不会自动重发。

恢复后的待核查表单禁止直接修改或生成新提交标识：

- **核查上次提交**：创建按原 request_id 查找；已存在就恢复确认并结束草稿。编辑读取当前记录，只有修订已推进且本次修改字段均一致时，说明当前内容符合上次提交；不会伪称已证明是哪次请求写入。其他修订变化保留草稿并提示显式载入最新版本。
- **重试同一提交**：只重发已加密保存的相同创建 ID/请求体，或相同编辑修订号/修改。创建去重与编辑乐观锁仍由服务端执行。
- 查不到记录不证明上次请求未执行，可能仍在处理；保留提交快照，允许用户明确重试原提交。不会把 GET 404 当作可安全换 ID 新建的证据。
- 放弃待核查草稿有明确提示：这不会取消可能已生效的服务端提醒，重新创建可能重复。服务端已接受而本机清理失败时，保留本机核查记录，避免离开视图后误当成从未提交。
- 已知提交前校验失败允许修改草稿；修订冲突仍要求显式载入最新记录。编辑载入不会悄悄覆盖服务端。创建/编辑 HTTP 在视图卸载或账号变化时撤销客户端等待，但不能撤回服务端已接受的动作。

一个账号当前只有一个提醒草稿；切换编辑对象前提示放弃当前修改，待核查提交要求先核查或明确放弃。全本机最多 20 个账号草稿。旧密钥库无新增字段时按空列表读取；草稿不是云端同步或自动发信队列。

## 模板与搜索

内置“提交周报”“会议准备”“每日待办复盘”。可把当前主题、正文、时区、重复规则保存为自定义模板，给出名称、应用或删除。模板不含日期、收件人、创建标识或旧修订；应用后必须确认下一次时间并明确保存提醒。自定义模板仅本机加密保存，按上述账号范围区分，每账号最多 30 个、全本机最多 100 个。

提醒列表支持主题/正文关键词、状态与重复规则筛选。按按钮提交查询，查询在服务端执行，覆盖全部匹配记录，不只是当前 20 条；`%`、`_`、反斜线按普通字符处理。成功改变筛选时重新开始 ID 游标窗口，翻页和刷新保持当前已应用筛选。请求失败保留旧列表与已应用筛选，编辑草稿不丢弃。结果字段/状态仍可能随并发操作改变，游标窗口不是数据库快照。

## 接口

- `GET /api/v1/personal/reminders/by-request/{UUID}`：正式账号范围内查询创建请求。找到返回当前 Reminder；其他账号或不存在返回相同 404，非法 UUID 返回不回显输入的 422，所有响应 no-store。
- `GET /api/v1/personal/reminders/page?...&q=...&status=...&recurrence=...`：q 最多 200 字符；status 为 active/paused/cancelled/completed，recurrence 为 once/daily/weekly。与现有 cursor/snapshot_id/limit 合用；旧列表接口保持兼容。
- `GET /api/v1/personal/reminders/export?limit=500&q=...&status=...&recurrence=...`：导出匹配的账号提醒与对应全部投递历史为 `geiit-reminders-v1` JSON。最多 500 条提醒、10,000 条投递记录、16 MiB；超过投递或字节上限返回 413，提醒数超出则 `truncated=true` 并保留最新 500 条。响应使用 attachment 与 no-store，不包含邮件正文、认证信息或其他账号数据。此导出用于个人留档，不是导入/恢复接口。
- 创建/PATCH 契约未变，没有新增数据库表或迁移。模板和草稿不上传服务器；服务端搜索词会到服务端，其代理/访问日志策略仍需后续部署核查。

- 前端全量 **84 文件/827 项通过**；后端 **581 通过/16 环境或隔离依赖相关跳过**。新增加密草稿/store 与界面测试共补充 10 项，后端个人记录定向集 44 项。覆盖锁库前冲刷、保存失败、清理失败回退、账号隔离、未知请求恢复/核查/重试、卸载取消和迟到响应、模板及筛选分页。
- `scripts/verify-reminder-edit.mjs` 使用生产 Web → 真实 FastAPI personal 路由 → 独立 SQLite 内存库，保留原 63 提醒/55 投递分页、冲突、DST/时区和人工结束用例；新增真实服务端接受 POST/PATCH 后仅丢弃客户端响应、刷新恢复/核查无重复、草稿/模板密文检查、搜索跨页与 390px 验收。最后连续三次完整通过，截图和结果在 `.tools/reminder-edit-qa/`，服务端动态回环端口自动关闭，零邮件。
- QA 曾出现两次初始或恢复表单保持禁用的超时。代码检查发现一条可导致该表现的路径：初始能力与列表请求使用 `Promise.all`，列表请求失败会同时丢弃成功的能力结果，令新建表单继续禁用。现改为分别应用成功结果；刷新时同样保留已成功的一侧，并显示失败一侧以便重试。生产浏览器验收注入“服务端列表 GET 返回 200、客户端丢失响应”，确认能力请求成功后新建表单可用；原完整场景连续三次通过。此前两次历史超时的具体请求仍无日志可证，故不能断言已确定当时的唯一根因。
- 诊断脚本现在仅记录提醒能力/列表的请求路径、方法、状态和失败字段状态，不记录请求正文或认证头。测试夹具直接覆盖合成正式用户依赖并复用固定对象，避免嵌套认证依赖并发查询 SQLite `StaticPool` 时偶发空用户；若 fixture 自身返回 500，结果会保留有限的服务日志尾部供排查。
- TypeScript、Web 生产构建、定向 ESLint、Ruff E9/F、差异检查通过。本批没有改 Rust、重跑 Rust 或重建原生安装包；现有 dev.9 包来自前一批，**不含本批草稿/模板/搜索改动**。没有使用真实业务数据库、调用真实模型、发信、推送或部署。
- 本机笔记/待办仍需显式保存记录，其未保存编辑尚未自动持久化；该功能仅覆盖服务端提醒表单。归档、批量导出、真实 Celery/邮件供应商联调仍待做。模板不是可视化工作流或任意触发器。
