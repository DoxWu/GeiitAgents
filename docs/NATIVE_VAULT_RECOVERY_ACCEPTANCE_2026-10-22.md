# Windows 工作台进程中断恢复验收（2026-10-22）

使用现有 dev.69 打包程序、Windows `10.0.26100 x64`、WebView2 `155.0.4283.62`，在全新隔离 profile 中完成四次启动及五项容量/恢复检查。本批只增加验证脚本和说明，没有改动应用运行代码、重建安装包或修改用户日常安装。

最终报告：忽略目录 `.tools/native-vault-recovery-20261022/run-FTMiaa/result.json`。其中保存四个阶段、两次实际结束的进程树、五项检查、二进制哈希和时延；同目录保留合成 profile、加密备份和恢复截图，不提交这些产物。`run-0FvvfZ` 是上一轮成功结果；之后加强其他 499 条记录、99 条草稿和原有集合的完整值比较，并以最终重跑为准。

| --- | ---: |

| 最后阶段 JS heap 单次采样 | 204,386,804 字节 |

JS heap 是最后阶段的一次采样，不是进程工作集、内存峰值或低配结果。开发机约 27.6 GiB 可见内存，上述时延也不是 SLA。

受测 EXE 为 `kb_qa_system/frontend/src-tauri/target-dev/release/geiit-workbench.exe`，15,450,112 字节，SHA-256 `A8AEF9F1B9C66DAF495B82F7AA25D785FDC63C83D48A6D78F092EAC5B3BFE0F2`，与上批 dev.69 standalone 相同。没有重复安装器升级/卸载测试。

从 `kb_qa_system/frontend` 执行：

```powershell
node scripts/verify-native-vault-recovery.mjs --exe src-tauri/target-dev/release/geiit-workbench.exe --output ../../.tools/native-vault-recovery-20261022
```

脚本只新建 profile，不接受已有 profile 或真实口令。Windows 原生窗口运行期间可能可见；应用不会安装到系统或替换已有程序。首次执行在已触发存储错误后错误地等待底层错误文字，而 UI 正确显示统一的“本机保存失败”，因此该轮失败；修正测试选择器后完整重跑成功。应用逻辑没有因该失败改变。
