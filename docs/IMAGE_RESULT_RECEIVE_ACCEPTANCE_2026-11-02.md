# 生图结果接收修复与验收

日期：2026-11-02。范围为正式应用代码、本地构建和隔离/已授权的供应商验证；未安装或部署。

## 根因与修复

用户反馈模型已生成图片，工作台却显示通用“检查模型名称、密钥与接口兼容性”错误。核对调用链后确认，输入参考图与生成结果曾共用1,500,000字节限制；桌面Rust下载、浏览器下载、内嵌Base64解析、服务端/BYOK代理以及图片草稿校验均可能拒绝大于此值的有效生成图。桌面前端还会把未映射的原生图片错误折叠成通用连接提示。因此这条路径足以解释该症状，但没有捕获到用户先前失败请求的原始响应，不能断言它是那次请求的唯一问题。

现在将输入图和生成结果分开限制：用户上传/参考图片仍为每张1.5 MiB；模型生成结果在应用端、Rust桌面层、BYOK/服务端和PPT设计中允许至8 MiB，与本机加密图片预算一致；包含Base64的生图模型响应允许至12 MiB。密钥库总图片预算仍为8 MiB，超过剩余预算时仍会拒绝保存并给出容量提示。生图界面把“结果过大”“无效图片格式”“安全下载失败”和“模型传输响应过大”分别映射为固定说明，不再让这些已辨别的接收问题显示为模型名或密钥错误。

现有的HTTPS/公网下载校验、图片签名检查、禁止重定向、禁止把API Key转发给图片CDN、用户输入图片限制、8 MiB加密库容量均保留。没有添加自动降级为纯文字生图的行为。
