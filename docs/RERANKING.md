# 云端知识库重排选择

在「设置 → 云端知识库检索 → 重排方案」选择：

- **保持现状（默认）**：沿用服务端现有检索配置，包括原来的 `ENABLE_RERANKING` 和 BGE Cross-Encoder 配置；不会新增 Qwen API 请求。
- **qwen3.7-text-rerank（主模型 API）**：召回候选后，通过阿里云重排接口重新排序，再将选中的片段交给问答模型。

选择自动保存在本机，按账号服务器与用户 ID 隔离，对后续云端知识库非流式问答、流式问答及重新生成生效。它不修改服务端全局默认，也不更改本地知识库的模型、文档或向量索引。全文文档对话不经过向量召回，因此不使用该设置。

## 配置与调用

Qwen 重排使用现有 `providers.yaml` 中第一项主 LLM 的 API Key 和 API Base，不复用备用模型，也不另存密钥。配置加载器读取当前后端工作目录的 `.env`，系统环境变量优先；不会将文件内容写入进程环境变量。旧 `OPENAI_*` 与新的 `ALIYUN_*` 回退关系保持一致。

依据[阿里云重排 API 文档](https://help.aliyun.com/zh/model-studio/text-rerank-api)，调用同一主机下的 `/api/v1/services/rerank/text-rerank/text-rerank`，使用 `model`、`input.query`、`input.documents` 和 `parameters.top_n`。它不是聊天补全接口。支持阿里云 DashScope 中国/国际/美国端点及 MAAS 工作空间端点；保留主配置的区域和工作空间，不自动切到其他地域。其他供应商或不兼容端点会跳过 Qwen 重排。

仅在明确选择 Qwen 后发送问题和已通过文档权限过滤的候选正文，可能产生额外供应商费用。最多 50 个候选，单片段最多 8192 字符、问题加候选最多 120000 字符；超过预算时保留原检索顺序，不静默截断正文。网络操作超时为 8 秒，不自动重试，不跟随重定向、不读取环境代理。响应有大小和耗时检查；返回索引、数量和分数必须完整有效，否则整批退回原检索 Top-K。

重排分数保存在独立的 `rerank_score`，不覆盖原始检索分数或来源元数据，也不表示答案正确率。API 失败、限流、权限不足、端点不支持或响应异常均记录脱敏降级日志，继续使用原检索 Top-K。

## 2026-10-20 验证范围

本机使用项目 `.env` 中的主供应商配置，单次合成问题与两段合成正文的 `qwen3.7-text-rerank` 真实请求通过。隔离测试覆盖默认不调用、账号/服务器隔离、设置保存、三类问答请求、权限范围、同数候选排序、索引映射、原始分数保留、异常响应、预算和超时降级。

随后在隔离 Docker PostgreSQL 16.14 + pgvector 中，从空库迁移并核对 `vector(1024)`，用真实主 Embedding 为三份合成资料建向量，验证权限过滤、真实 Qwen 重排及非流式/流式 RAG。检索结果含 `rerank_score`，命中相关的本人资料；回答符合合成资料，来源未包含另一账号的私有资料，流式有正文 chunk 且只有一个 done。随机测试库已删除。

这次是服务层合成资料联调，关闭了 query rewrite、intent detection、conflict detection 和原有 BGE 重排，以限定检查范围；没有覆盖 HTTP 上传/登录、Celery、旧目标库跨维度迁移或业务回答质量。另一个真实 pgvector 回归验证同维度、`embedding_space=NULL` 的旧片段在显式重新生成向量后可检索，不代表已有 1536 维列会自动变成 1024 维。
