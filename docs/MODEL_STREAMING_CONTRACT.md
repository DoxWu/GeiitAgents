# 工作台聊天流式结束与停止原因

更新：2026-09-29。本约定最初用于浏览器本机直连、Tauri 本机直连、个人云端转发和授权账号模型四条**工作台聊天**路径。dev.15 的文档生成和本地库来源回答已复用本契约，具体预览、成果与导出规则见[非聊天入口流式说明](NON_CHAT_GENERATION_STREAMING.md)。现有云端知识库的 `apiClient.streamPost` 保持原状，不能推断所有应用入口都已具备相同的结束验证。

## 完成条件

- 兼容供应商 SSE 支持 UTF-8 分块、中文/emoji、首部 BOM、CR/LF/CRLF、多行 `data`、注释、role-only 和 usage 空 choices 事件。
- 只选择 index 为 0 的回答；仅一个 choice 且未提供 index 时也接受。不合并其他候选、不执行工具调用、不将数组/多模态内容自动转换为文本。
- `[DONE]` 或目标 choice 的非空 `finish_reason` 才证明供应商结束生成。只收到文本后的 EOF、非法编码/JSON、error 事件、无效内容类型或空回答均失败。最后事件 JSON/标记完整但没有空行结尾时允许在 EOF 解析。
- 如果服务忽略 `stream:true` 而返回完整兼容 JSON，可一次性返回非空文本；这不代表逐字流式，也不证明语义完整。
- 本应用的转发 SSE 必须出现 `type:done`。done 中的完整正文必须与已接收增量一致；错误、格式损坏、正文不匹配或缺少 done 不能被解析器忽略后变成成功。
- 到达结束标记、取消、回调失败、错误 HTTP 状态或不支持的响应类型后主动关闭响应。取消/锁库不保存未完成文本，也不会自动重放或静默改用其他模型。

## 用户可见的停止原因

| 归一化值 | 显示及保存含义 |
| --- | --- |
| `stop` | 模型已结束生成；不保证事实正确或用户任务全部完成 |
| `length` | 达到模型输出上限，明确提示回答可能不完整 |
| `content_filter` | 输出受到模型服务限制，明确提示可能不完整 |
| `tool_calls` | 模型请求了工具；普通对话未执行这些工具 |
| `unknown` | 只有 DONE、JSON 未给原因，或供应商原因不在支持列表；不暴露原始未知值 |

`WorkMessage.finishReason` 为兼容旧加密库的可选字段；新工作台回答保留归一化原因，界面和 Markdown 导出都展示，刷新解锁后恢复。旧消息缺少原因时不回填虚构状态。达到输出上限的非空回答可以保留，但必须带上述提示；空回答仍报错。

输出 Token 配置仍为可选。没有配置时，个人请求和本机请求不发送 `max_tokens`；账号聊天复用服务端选中模型、Key 和 temperature，沿用该文本配置不发送视觉专用的 max_tokens 字段。工作台长对话的完整上下文仍保存在本机并用于请求，界面默认只渲染最近 20 条，早期消息可分批加载；详见[长对话分页](WORKBENCH_LONG_CONVERSATIONS.md)。

## 后端与资源边界

- 私人转发继续使用原 DNS 公网校验/IP 固定/HTTPS/认证/限流，只把临时 Key 放请求头，不保存到注册表、缓存或任务。当前请求不重试，不跟随重定向，不依赖环境代理；错误不回传上游原始正文。
- 账号聊天新增 `OpenAITextClient.astream_workbench`，由原模型管理器选择客户端；Ollama 继承此能力。使用严格 HTTP 读取，保留原 SDK 文本封装会丢掉的终止标记。原知识库 `astream`、共享配置和工具实例不变；本次工作台调用无 SDK 隐式重试或中途切换模型。沿用所选客户端熔断器，失败/成功会参与其健康状态。
- 尚无该方法的未来专有客户端会失败，不回退到无法证明结束的普通字符串流。需要实现相应适配后才能使用。
- 上游响应上限 2 MiB，文本最多 1,000,000 个 UTF-16 单元；转发前端额外允许最多 16 MiB 封装流，以容纳每个增量的 JSON 包装和最终全文副本。超限时拒绝继续解析/输出，不能把条数/Token 配置当作字节预算。
- 工作台请求控制器为 120 秒，Rust HTTP 为 115 秒；后端工作台流为 120 秒总限制、HTTP 90 秒读超时/10 秒连接超时。账号工作台严格传输不再使用旧 SDK 的首字重试策略。取消已在本机 HTTP fixture 验证关闭连接，但供应商是否立即停止生成/计费仍取决于供应商。
- 新增转发 `done.finish_reason` 字段，旧客户端可忽略。新客户端单独更新只能验证“后端给了 done”，**前后端匹配更新**后才能获得上游结束证明；旧后端曾可能在上游截断后仍生成 done。
- 非流式账号完成接口仍使用已有 SDK 字符串封装，不把它称作已完成相同的严格终止验收。dev.15 文档/本地库回答已主动使用严格流式接口，不再经过该完整返回路径。长对话分页、多模态和专有协议仍待推进。

## 实现与证据入口

- 前端 `src/services/modelStream.ts`、`workbenchModel.ts`：严格响应读取，工作台独立转发传输；原通用知识库 SSE 不变。
- 原生 `src-tauri/src/local_stream.rs`：保留严格解析并返回归一化原因；按 index 选取 JSON/SSE 回答。
- 后端 `app/core/model_text_stream.py`：私有/账号流共用字节解析；路由用 `aclosing` 管理生成器并传递原因。
- `kb_qa_system/test_fixtures/model_text_stream.json`：三种语言共用协议样例，每个字节分割边界验证，覆盖成功/停止原因/截断/错误/空内容/多 choice。
- `frontend/scripts/verify-native-stream.mjs`：默认最终开发 exe；`--web`、`--relay`、`--account` 分别验证生产浏览器三条路径。全部使用动态端口、隔离浏览器数据和合成资料；后两者运行真实 FastAPI 路由与 HTTP 传输，仅替换账号认证、限流与上游定位。不是线上账号/真实供应商/计费验证。

每条路径验证增量中文、两对话并行、停止/锁库关闭 HTTP、无结束标记断流失败且不持久化、JSON 回退、HTTP 错误脱敏、length/filter 原因、结束标记后关闭仍开放的上游、加密刷新恢复和包含停止原因的 Markdown 下载。浏览器另验 390px。当前结果/截图在 `.tools/model-stream-qa/{web,relay,account,native}/`；最终测试数量与安装包以 [工作记录](WORK_LOG.md) 为准。
