# 本机文件整理、故障恢复与撤销

最后更新：2026-09-29。移动/撤销主体说明及下方测试为 dev.10 历史验证；dev.13 新增独立的 [MD/TXT 内容编辑与版本恢复](LOCAL_TEXT_EDITING.md)，包含写前加密快照、差异确认与只读核验。未推送、部署或正式发布。

## 已接入能力

- 工作台“文件整理”可以选择普通文件生成只读清单，或明确授权一个可写目录，预览后应用命名变更；也可以选择第二个目录，跨目录移动并按需保留原名称。
- 只处理所选目录的可见文件，不进入子目录，不上传文件内容，不调用生成/向量模型。选择普通文件会清除旧的目录句柄。
- 每批最多 500 个可整理文件，总计 256 MiB，单文件 64 MiB；超过限制明确拒绝，不静默截断。
- 文件名预检拒绝路径、Windows 保留设备名、尾部空格/点和其他不安全名称；按 NFC 与小写检查碰撞。只改大小写、相互换名以及覆盖现有目标均不支持。
- 本机加密库最多保存 100 条整理/移动/撤销记录。记录包含两个目录显示名、原生目录身份摘要、源/目标文件名、字节数、SHA-256、暂存位置、状态与时间；不包含文件内容、绝对路径、原生授权 token 或持久目录权限。旧记录继续兼容。
- 完成后可以预览并明确确认撤销；刷新或重新打开后必须重新选择原目录。跨目录撤销先按原记录选择两个目录，预览时自动交换移动方向，再次确认才执行。导出的 Markdown 清单和 JSON 记录是明文。

## Windows 原生目录与轻量化

- Windows 桌面使用真实系统文件夹选择器（Rust `rfd`），不依赖 WebView2 的 `showDirectoryPicker`。Web 继续使用 File System Access；不支持该接口时仍可生成只读清单。其他桌面平台尚未接入此原生桥。
- `organizer_pick_directory` 只接收临时会话 ID，不接受前端路径；选择成功后返回随机 token、目录显示名和身份摘要。`organizer_access` 允许在授权目录内 list/stat/create/hash/copy/remove，以及 dev.13 的受限 read_text/write_text；拒绝路径分隔符、绝对路径、ADS、设备名称及未知字段。`organizer_release_directory` 释放授权。能力仅授予打包的 main 窗口，未向模型开放这些命令。
- 目录及祖先保持禁止删除/替换的句柄。每个原生文件操作期间另加短期禁止目录数据写入的锁，重新核对身份和 reparse 标志，防止路径在解析时被改为联接；不长期阻止目录内其他文件重命名。普通文件拒绝 reparse point 和多硬链接，原生创建使用 `create_new`，复制只写已登记的空文件。
- 摘要与复制留在 Rust，用 64 KiB 缓冲区处理；移动/整理界面只接收元数据，不将整个文件通过 JSON/IPC 传输。dev.13 的主动文本编辑单独允许最多 256 KiB UTF-8 内容通过 IPC。浏览器摘要仍可能读取最大 64 MiB 的文件，不能将原生缓冲区大小当作整个应用内存占用。
- 删除在同一个禁止外部写入/删除的文件句柄上检查身份与 SHA-256，再使用 Windows `FileDispositionInfo` 删除；不使用“检查路径后再按路径删除”的竞态方式。整个批次仍不是文件系统事务，各次操作之间其他程序可以改变文件。
- 离开整理视图、改选文件或锁库卸载界面时释放界面授权；在途操作单独持有引用，直到补偿完成才释放。关闭进程全部失效；刷新后 UI 不保留权限，新会话首次选目录清理旧授权。每个会话最多 8 个授权目录，目录枚举最多 5000 条（包含子目录/隐藏文件），超限拒绝。

## 执行及故障边界

1. 重新读取目录，检查目标未占用、源文件大小/预览修改时间，计算源内容摘要。撤销还要求与历史摘要一致。
2. 首次磁盘写入前，将 `running` 记录写入本机加密库。保存失败不修改目录。
3. 在源目录创建 `.geiit-stage-<记录 UUID>-<序号>` 暂存副本，逐个核验摘要。
4. 从暂存副本写入目标并核验；再次检查源及目标后才删除源文件。
5. 全部源删除后记为完成；之后清理暂存失败只附带警告和保留位置，不尝试倒退整批操作。

每个成功创建的文件立即登记。写入失败后终止 writer，不再调用可能提交数据的 `close()`。删除操作可能在生效后仍抛错，因此删除前登记尝试，并在补偿时重新读取磁盘暂存文件，不依赖可能已经失效的旧 `File` 对象。

未到完成点而发生错误/取消时，尝试从暂存恢复已删除源文件。仅在核验源完整后才清理对应目标与暂存；恢复失败、文件被替换或内容改变时保留副本并标记需要人工检查。不自动删除用户或其他程序修改过的文件。

这是一套带补偿的复制/删除流程，**不是操作系统的原子重命名或文件备份**。浏览器缺少排他创建及“核验后条件删除”接口，无法保证与其他程序同时操作目录的安全性；整理期间必须避免外部编辑。同源窗口在支持 Web Locks 时互斥，当前进程也有互斥；这些锁不能约束外部编辑器或不同浏览器。

复制会产生新文件：修改时间、ACL、扩展属性和备用数据流等元数据不保证保留。撤销只恢复位置、名称与已核验的主文件内容，不保证恢复这些元数据。正常流程最多同时持有源、暂存、目标三份数据，源目录需预留一份暂存空间，目标目录需预留一份文件空间；同目录则额外约两倍批次大小，浏览器 writer 还可能占用临时空间。尚无低配设备极限规模测量，也未在第二个物理卷或网络共享上验收。

## 加密保存、中断和核验

| 状态 | 含义及可执行操作 |
| --- | --- |
| `running` | 执行中；控件禁用，可请求停止并恢复 |
| `succeeded` | 已完成；允许预览撤销。若有暂存清理警告，记录仍需保留 |
| `failed` | 未应用或源已恢复；不代表历史永远与目录一致 |
| `interrupted` | 重开时发现旧 `running`；结果未知，先核验，绝不自动重放 |
| `needs-attention` | 混合状态或补偿不完整；保留记录和副本，人工检查 |
| `undone` | 已由成功撤销操作关联标记；不能再执行同一次撤销 |

“核验目录”只读检查全部源/目标的存在及摘要，判断已应用、未应用或混合，并列出仍在源目录的暂存位置。跨目录记录必须同时选择两个目录；原生记录核对卷/文件 ID/创建时间构成的身份摘要，选错同名目录也拒绝。浏览器及旧记录没有此身份字段，仍需用户确认选择了正确目录；显示名不能作为身份凭证。核验不自动移动/覆盖/删除文件，也不擅自选择应恢复的版本。

锁定会立刻清除内存中的记录并取消执行；补偿可能仍在进行。进程级运行标记直到旧操作完全结束才释放，重新解锁也不能提前启动另一操作。锁定后无法写入加密结果，重开按中断记录核验。

文件操作已完成但最终加密保存失败时，保留完成的内存状态并提示“文件可能已经变更”。“重试本机保存”只补存记录，不重放文件操作；若直接关闭，重开可能读到 `interrupted`，应先核验。未核实、有保留副本或存在待核验撤销的原记录禁止删除。

撤销是独立操作，同样先记录、校验、暂存、补偿。目标内容被后续编辑或原文件名被占用时拒绝撤销，不能覆盖后来文件。中断撤销经核验确已应用后，会将原记录标记 `undone`。
