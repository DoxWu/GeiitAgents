# 工作台加密备份与恢复

更新：2026-09-29。工作台导航中的“工作台备份”用于迁移或保护整个本机密钥库，不依赖登录、模型、服务端或本地向量模型。备份属于当前浏览器 origin / 客户端数据目录，不按云端账号划分。

## 包含范围

| 数据 | 处理 |
| --- | --- |
| 模型连接 | 包含连接配置；API Key 默认排除，必须主动勾选包含 |
| 对话与知识回答记录 | 包含已进入密钥库状态的消息、模型信息和停止原因 |
| 办公任务与成果 | 包含任务、工具记录、Markdown / SVG 及版本关系 |
| 可视化工作流 | dev.16 起包含定义/布局/连线、运行修订与输入快照、节点检查点；恢复不自动运行 |
| 本机笔记与待办 | 包含正式记录、归档状态、原始编辑草稿与固定时区 |
| 邮件提醒 | 仅本机草稿、提交核查快照与模板；不包含服务端提醒和投递历史 |
| 文件整理与文本编辑 | 包含整理历史、受限文本草稿、前后确切文本和摘要 |
| 本地知识库文档、向量及模型配置 | 不包含，使用[本地知识库独立备份](LOCAL_KNOWLEDGE_BACKUP.md) |
| 模型权重、登录凭据、云端数据库、外部目录文件 | 不包含；恢复也不重新获取目录授权 |

尚未进入工作台状态的页面表单输入不包含。提醒草稿中已有的提交快照仍保持原账号与服务器标识，恢复不重新提交邮件请求。API Key 选项只控制模型连接中的密钥字段；如果用户自己把凭据写入聊天或笔记正文，备份不会自动识别并删改正文。

dev.16 增加工作流集合与节点字段，含这些字段的 v1 备份需要 dev.16+ 恢复；旧版本严格拒绝未知字段。工作流页面未点击保存的修改不属于持久草稿，亦不进入备份。详见[工作流说明](VISUAL_WORKFLOWS.md)。

dev.18 文本版本新增批次分组字段和 `not-started` 状态，含这些数据的备份需 dev.18+；校验批次索引、数量、目录与条目一致性，允许已删除部分记录的历史。临时批次预览不入库、不进入备份；恢复不授权目录或自动续跑。见[批量文本编辑](BATCH_TEXT_EDITING.md)。

## 用户流程与故障保护

1. 解锁工作台，等待或停止正在运行的模型、文件和成果导出操作。输入独立备份口令，确认是否包含模型 API Key，下载 `.geiitwork`。
2. 导出立即冻结当前内存快照，包括已进入持久草稿状态但尚在 400 ms 合并等待中的编辑。导出不依赖先成功写入 localStorage，所以配额故障时仍可备份当前内容。它不代表之后的修改或下载必然已保存，用户需确认下载文件。
3. 恢复入口在锁定状态可用，未创建密钥库的新设备也可使用。选择文件，输入备份口令和恢复后的新解锁口令；预检查只在隔离内存中解密、校验并重新加密，不写当前密钥库。
4. 预览显示备份时间、各集合数量、包含的 Key 数量和是否替换已有库。用户勾选整体恢复后提交。当前实现整体替换，不合并，也没有选择部分集合恢复。
5. 确认时重新检查会话代次、预览标识、文件操作是否真正结束和预检查时的原密文。其他窗口已更改密文时拒绝覆盖；单次 `setItem` 因配额/存储错误失败时保留旧库及预览，可以释放空间后重试。
6. 成功后仍保持锁定，以新口令正常解锁。历史 running 状态沿用现有逻辑标记 interrupted，不自动执行模型、工具、邮件或磁盘写入。文件历史还需重新授权并核验当前文件，显示的旧目录身份不等于恢复了目录权限。

取消、离开备份页、重新解锁或锁定会使正在进行的转换及预览失效；已经开始的 Web Crypto 运算不能物理中止，但迟到结果会丢弃，不触发下载或写入。无效口令、损坏、未知字段/版本和内容超限都会在写入前拒绝，不输出导入内容或密钥作为错误详情。

当前客户端的常规保存和恢复提交共用短时 Web Lock，并在临界区中比较原始密文。Web Locks 不可用时仅进行同步比对与写入；旧客户端、不参与锁的程序和外部存储修改不能获得跨进程事务保证。它也不是断电事务、自动远程备份或无限容量存储。

## 格式与实现契约

- 外层格式 `geiit-workbench-backup`、版本 1；PBKDF2-SHA256 固定 600000 次、随机 16 字节盐；AES-256-GCM、随机 12 字节 IV、AAD `geiit-workbench-backup:1`。外层只含算法参数和密文。
- 内层 `{ version: 1, exportedAt, data: VaultData }`；时间和数量不公开在外层。每次导出独立随机盐/IV，与原工作台口令和本地加密信封分开。
- 口令 4–256 个字符；建议较长独立口令。四位是最低交互限制，不能抵御弱口令离线猜测；备份口令遗失无法恢复。
- 加密文件最多 24 MiB，明文负载最多 16 MiB；本机密钥库也会在加密前拒绝超过 16 MiB UTF-8 快照。Base64、UTF-8、对象字段、集合数量与文本长度均有界。实际 localStorage 配额可能远小于上限，预检查成功不等于最终一定能写入。
- 导出和导入共用严格校验：未知字段拒绝、ID 唯一、任务/工具/成果引用、成果摘要、文本摘要与容量、合法文件名及 SVG 标签/属性允许清单。支持旧库缺少可选集合；不静默丢弃未来版本的字段。未知/损坏的现有历史可能需要后续迁移器，当前不能选择跳过损坏项。
- `src/services/vaultBackup.ts`：`exportVaultBackup`、`importVaultBackup`、`prepareVaultReplacement`；`vaultBackupSchema.ts`：校验规则。`privateVault.ts`：共用写锁。
- `src/store/workbenchStore.ts`：`exportWorkbenchBackup`、`prepareWorkbenchRestore`、`commitWorkbenchRestore`、`cancelVaultTransfer`。公开预览只保留计数和随机 ID，待提交数据为新口令下的密文，密钥不进入 Zustand 公共状态。
- `src/components/workbench/WorkbenchBackup.tsx` 为按需加载页面；没有新增运行依赖、模型下载或服务端接口。主 store 通过动态导入调用备份实现。
- dev.15 新增文档成果/工具的可选 `finishReason`，恢复时保留；临时流式预览不备份。旧 dev.14 恢复包含这些字段的新备份会按未知字段拒绝，应使用相应或更新客户端。
