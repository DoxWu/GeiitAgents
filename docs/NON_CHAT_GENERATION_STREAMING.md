# 文档生成与本地知识库回答流式处理

更新：2026-09-29。文档生成和本地知识库的来源回答已接入[工作台严格流式传输](MODEL_STREAMING_CONTRACT.md)。浏览器本机、Tauri 本机、个人云端转发和授权账号模型沿用已有接口；没有新增模型端点、改变 E5 配置或改动现有云端知识库。

## 生成过程与完整性

- `startDocumentTask` 与 `answerKnowledge` 始终传入增量回调，包括调用方未要求展示预览的情况，确保走相同的严格传输路径。请求不会因中断回退到非流式账号 SDK 或其他模型。
- SSE 必须有有效结束标记，应用转发必须有正文一致的 done；只收到文本后 EOF 会失败。供应商返回完整 JSON 时仍允许一次返回，但不能把它称为真正的增量输出。
- `length` / `content_filter` / `tool_calls` 的非空回答可保留，明确显示停止原因与局限。`unknown` 表示有传输结束证据但缺少可识别原因；不虚构 stop。任务状态 succeeded 只代表获得并保存了成果，不保证文档完整、事实正确或工具已执行。
- 文档任务先保存 running 记录再调用模型，成功后原子保存成果与执行记录。失败、取消和未正常结束的片段不成为成功成果。最后本机写入失败仍遵循原有规则：保留内存成果供重试保存，不再次调用模型。
- 本地库回答保持临时结果，只有明确点击保存才成为工作台只读记录。选择模型/来源、重新检索、离开页面或锁库会清除相应预览与授权；每次云端请求重新确认出站。来源及问题使用请求时快照，不发送向量或整个库。
- 停止、锁库、登出云端账号和离开来源回答页面通过现有 AbortController 关闭传输；迟到的回调不能填回新请求或锁定状态。文档任务切换页签仍可继续，锁库/关闭才中断，延续原持久任务设计。

## 有界预览与持久元数据

`services/generationPreview.ts` 在首个片段到来时立即显示，后续以 60 ms 窗口合并。预览最多保留前 16000 个 UTF-16 单元，继续计数全部接收长度，并明确提示显示范围。正文以纯文本展示，不在每个增量上运行 Markdown 解析或外部资源加载。最终传输仍使用现有 1000000 字符限制并校验完整正文，预览截短不等于最终成果截短；取消时清除定时器和缓冲。

文档预览位于 `workbenchStore.generationPreviews`，不进入 `VaultData`；知识回答预览只在组件状态中。`WorkArtifact.finishReason`、`ToolRun.finishReason` 和 `KnowledgeAnswerArtifact.finishReason` 为可选字段，兼容旧历史。来源回答归档将原因同时保留在 `WorkMessage.finishReason` 和独立 Markdown 内容中，刷新、导出和备份后仍可见。

手动编辑的新文档版本不继承供应商原因，因为它已是用户修改内容；原模型版本与工具记录继续保留。明确恢复旧版本时复制该版本的停止原因。工作台备份校验器认识这些可选字段，包含它们的备份需使用 dev.15 或后续客户端恢复；dev.14 会按未知字段拒绝，不静默丢弃。

## 导出行为

- 新生成文档的非 stop 原因会以“生成状态”说明附在 Markdown、HTML、DOCX 导出开头，提示核对完整性。旧版本没有原因时不补造；stop 不额外改变文档正文。
- 原始成果内容与 SHA-256 不变，界面展示的成果摘要仍针对原始正文；带说明的 Markdown/HTML 下载字节不应拿该摘要比较。DOCX 执行记录继续记录实际下载字节的独立摘要。
- 来源回答 Markdown 含模型、停止原因、问题和实际选择的原文快照；保存/导出不再调用模型，不自动续写或重试。

## 本次验证边界

前端全量 **98 文件 / 946 项通过**，本批新增 17 项。包括限频/预览容量、迟到回调、停止/锁库关闭 reader、非聊天路径实际解析器的严格 EOF、转发正文不一致拒绝、停止原因的加密保存/备份往返和版本恢复、来源回答保存/导出。TypeScript、相关 ESLint、Web 生产构建通过。后端和 Rust 业务代码未改，本批不重跑其历史全量测试。

`frontend/scripts/verify-generation-stream.mjs` 支持默认 Web、`--relay`、`--account`、`--native`。使用动态端口、隔离浏览器/WebView2 与合成模型 HTTP 服务，每条路径 8 次请求：

- 文档生成增量中文/emoji、length、实际 Markdown/HTML/DOCX 下载、无结束标记 EOF、停止及锁库断开。
- 本地库来源回答增量、content_filter、带来源的 Markdown 下载、明确保存、无结束标记 EOF、停止与离页关闭、刷新解锁保留原因；云端两路径再次核验逐次授权。
- relay/account 使用真实 FastAPI 路由与严格 HTTP 传输，账号认证、限流、模型选择和上游地址为 fixture；不是线上登录、真实供应商或计费验证。
- 检索使用确定性 Worker 与预置本地索引，专门隔离验证生成入口；本批未下载模型、未重跑 E5 推理/检索质量，默认 E5 参数与向量库不改。
- DOCX 只检查实际下载 ZIP/XML 中的状态说明，不代表逐页渲染或版式验收。原有 DOCX 分页运行时缺失仍未解决。
- Web 390px 与相关截图检查，结果位于 `.tools/generation-stream-qa/{web,relay,account,native}/`。最终桌面产物和验证状态以[工作记录](WORK_LOG.md)为准。

旧 `verify-local-answer-live.mjs` 已适配当前流式路径，但其 Python helper 本质为完整返回，测试脚本将结果包装为缓冲 SSE，原因标为 unknown。它不能证明上游严格流式结束；本批仅做语法检查，没有运行该历史真实 E5/供应商脚本。

已完成：本地知识库来源回答支持页面内临时多轮追问。首轮请求把来源快照放在首条用户消息中；后续请求携带已完成的问答轮次和当前追问，最多保留 8 个前序轮次，并限制来源与历史总长度。云端每一轮都重新要求出站授权；切换来源、模型、检索问题、离开页面或锁库会清除线程。追问失败/取消会保留上一轮回答和当前输入草稿，只有完成后才更新线程；显式保存/导出会包含完整问答和来源快照，仍不发送向量或整个本地库。
