# 办公客户端第一批实现

> 本文记录 2026-09-17 桌面批次，测试及产物为当时结果。后续进度统一见 [工作记录](WORK_LOG.md)。2026-09-19 已确认的客户端本地知识库默认采用 `Xenova/multilingual-e5-small`，仅用户主动启用后添加，与现有云端库分开；该功能尚未包含在本批代码/安装包中，规格见 [本地库实施约定](LOCAL_KNOWLEDGE_BASE_SPEC.md)。

本批完成 Tauri 2 Windows 外壳、独立工作台、本机 Markdown 预览、自定义兼容 Chat Completions 的模型连接和本机加密会话。现有知识库页面继续保留。文档生成/转换、图表工具、待办邮件、任务恢复和工作流画布尚未实现，下一批在此基础上接入工具执行器。

## 本轮调整

- 最大输出 Token 改为可选，新增连接默认留空。留空时浏览器、本机 Rust 和云端 BYOK 转发均不发送 `max_tokens`，使用供应商默认；连接测试也不再强制 8 Token。填写时只校验正整数及传输范围，实际模型上限由服务商决定。已有连接保存的显式值保留，可清空后重新保存。
- 创建本机密钥库的口令最低长度改为 4 个字符，保留长口令支持；加密算法与派生强度不变，短口令的抗离线猜测能力较弱。已有密钥库仍使用原口令，不自动更换。供应商 API Key 不截短。
- 新增 `GET /api/v1/private-models/account` 查询账号模型可用性，`POST /api/v1/private-models/account/complete` 调用服务端现有文本模型。权限沿用现有用户类型：启用的正式用户或管理员可用，游客和停用账号不可用。每次调用后端重新校验；用户不能在此接口指定上游地址、密钥或任意模型。
- 无个人连接时，账号获准且服务端有可用模型，工作台默认选择“账号云端模型”。已有个人连接仍可手动切换账号模型；个人连接失败或被删除时不会静默转为其他云端模型。退出/切换账号清除可用状态并取消进行中的账号请求。
- 账号模型使用部署者原有服务端配置，模型供应商凭据不会下发客户端；用户自行填写的 API Key 继续仅本机加密保存、云端临时使用。此改动不涉及新增授权数据库表。
- 本轮验证：相关前端 22 项、后端及既有模型适配共 98 项、Rust 地址测试通过；浏览器验证包含 4 位口令、默认省略 Token、无个人连接的正式账号调用与游客禁用。完整真实云端联调仍需部署后端及服务端模型配置。

## 已实现

- `/workbench` 无需登录即可使用本地功能；桌面启动默认进入工作台。网页设置和聊天侧栏增加入口。
- 多个独立对话，最多三个并行请求；切换对话不串回复；支持取消、超时、删除和导出 Markdown。当前是完整文本响应，非流式与后台持久任务。
- 模型配置：名称、Base URL、模型名、API Key、输出上限、连接测试。仅兼容 `/chat/completions` JSON 接口；供应商专有协议、工具调用、图片输入、能力检测后续增加。
- 本机直连适配 Ollama、LM Studio 等兼容接口。只允许 loopback；桌面通过 Rust 请求，无需配置浏览器 CORS；本批不安装模型服务或下载模型权重。
- 本地 `.md/.markdown` 文件最大 2 MiB，UTF-8，只读预览/源码，GFM 表格支持。禁用 HTML、外链导航和远程图片加载；文件仅在用户勾选后发送给所选模型。当前对话输入另有字符总量限制。
- 工作台按路由加载，复用已有 Markdown 库；不把 Python、数据库、Redis 或模型权重打包进客户端。

## API Key 策略

用户模型 Key 与工作台对话整体加密后保存在当前客户端的 WebView/browser localStorage 中，明文 Key 不进入 Zustand 公共状态。使用 PBKDF2-SHA256（600,000 次、随机 16 字节盐）派生不可导出的 AES-GCM-256 密钥，每次写入随机 12 字节 nonce；用户口令不保存、不上传。此方案是口令加密库，尚未接入 Windows Credential Manager。

15 分钟无键盘/指针活动自动锁定，手动锁定、页面关闭清理应用可访问的明文状态并取消请求；已交付给网络库的请求可能仍在远端处理，不承诺内存物理擦除。口令遗失无法恢复。浏览器与桌面、不同 origin 的库互不共享；同一设备库也不按知识库账号拆分，使用者应独立保管口令。

云端接口 `POST /api/v1/private-models/complete` 要求现有账号认证及限流。模型 Key 仅放 `X-Model-Api-Key` 头，业务参数体不接受凭据字段；服务器在当前请求内创建独立 HTTP 客户端。该路径不写模型注册表、数据库、缓存或 Celery，不返回上游错误体；Sentry 丢弃该路径事件/事务并禁用局部变量采集。响应禁止缓存。前后两段均禁用重定向，防止凭据随跳转发送。

云端模型地址限 HTTPS 公网 443，校验全部 DNS 结果并固定解析 IP，保留原 Host/TLS SNI，拒绝私网、回环、元数据地址和重定向。自建内网模型当前不经云端转发。

上线部署还必须让网关、反向代理、WAF、APM 不记录此接口的请求头/请求体，也不要开启 HTTP 调试抓包。当前仓库不能约束外部基础设施或模型供应商的记录策略。“云端只用不存”不意味着第三方模型供应商无法看到 Key 或用户主动发送的文档。

客户端锁定/离线时，云端没有用户 Key 可继续调用模型。后续工作流需进入等待设备状态；已经排定且无需模型处理的邮件提醒仍可由服务端调度。

## 运行与配置

在 `kb_qa_system/frontend`：

```powershell
npm install
npm run dev -- --host 127.0.0.1 --port 1420 --strictPort
# http://127.0.0.1:1420/workbench
npm run desktop:dev
npm run desktop:build
```

桌面编译需要 Rust MSVC、Visual Studio C++ Build Tools、Windows SDK；运行需要 WebView2。当前机器的临时 Rust 安装在仓库 `.tools/cargo` 和 `.tools/rustup`，未修改全局 PATH，编译时需设置相应 `CARGO_HOME`、`RUSTUP_HOME` 和进程 PATH。

`.env.desktop` 默认后端 `http://localhost:8000/api/v1`，避免 Web 生产模式的相对地址错误指向 Tauri 自身。发布到实际服务时，在构建进程设置 `VITE_API_BASE_URL=https://你的后端/api/v1`；该变量只能放地址，不能放 Key。编译时环境变量优先于文件。Web `.env.production` 保持原用法。

后端的 `CORS_ORIGINS` 需包含实际网页域名及 `http://tauri.localhost`（Windows）、`tauri://localhost`（其他平台）、开发用 `http://127.0.0.1:1420`。默认开发列表已补，生产环境显式覆盖时需要同步追加。请求头已放行 `X-Model-Api-Key`。云端功能需要部署本批后端；本机功能无需启动后端。

模型填写示例：

| 类型 | 调用方式 | Base URL | Key |
|---|---|---|---|
| Ollama | 本机直连 | `http://127.0.0.1:11434/v1` | 通常留空 |
| LM Studio | 本机直连 | `http://127.0.0.1:1234/v1` | 按本机服务配置 |
| 兼容云端模型 | 云端临时转发 | 供应商文档提供的 HTTPS 根路径，如 `https://api.example.com/v1` | 用户自行填写 |

模型名必须对应服务中实际存在/已加载的模型。Base URL 不填完整 `/chat/completions`，也不能包含 Key 查询参数。
